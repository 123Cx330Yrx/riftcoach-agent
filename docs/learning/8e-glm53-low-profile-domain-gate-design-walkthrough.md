# 8E 学习材料：低思考候选独立领域门怎么设计

## 先区分两个问题

RQ-221 的一次无工具探针只说明“低思考 + 4096 能把一个冻结请求完成”。领域门要回答的
是另一件事：模型能否在真实 Skill、知识检索、事实/引用检查、评测和发布控制下完成一份
可交付复盘。前者是响应完成度，后者才接近产品能力；不能把前者的成功直接升级成后者。

## 为什么不能重跑旧考卷

旧考卷的题目、fixture、注入 marker 和失败位置已经被开发过程看见。即使只换模型档位，
也会把“对这套题的修复”误当作泛化能力。新的 held-out 必须在规则冻结后创建，执行时只
拿到 Input Plan 和实际 Context，阅卷标准留在执行器之外，这就是 oracle-blind。

## 为什么要有评测作用域

产品运行档案是全局安全边界；把候选 profile 注册进去，任何普通构造路径都有可能误用它。
因此候选要带一个只有评测入口能持有的作用域令牌。共享执行链只接收窄的“请求策略”，
最后的预算包装器再覆盖调用者和模型能影响的字段。这样可以复用 Agent/RAG/Harness，
又不会把实验档案悄悄变成产品默认。

## 领域门的固定边界

新门仍用三个匿名案例：正常近期复盘、用户数据夹带指令、检索知识夹带指令。每案例最多
四次请求、全域最多十二次；每请求最多 4096 输出，Agent/工具 90 秒、传输 120 秒；总 token
墙为每案例 24,000、全域 72,000。没有重试、恢复或修订，首个不安全失败就停止。真实
成功必须同时满足 Agent 完成、知识证据、事实/引用/注入检查、Evaluation 至少 85 和
Harness 发布；deterministic fallback 在候选评测中关闭，避免“回退成功”掩盖模型失败。

## 后续执行顺序

先做零网络 TDD，证明候选作用域、请求覆盖、预算和脱敏；再取得同 SHA 的低思考 G53-3-L，
随后创建并冻结新考卷。只有这些身份都通过 no-I/O admission，才在另一次明确授权下发起
一次领域观察。无论结果好坏，回执都不可覆盖；领域门也不等于黄金切片、安全部署或 8F。

## 面试表达

> 我没有把一次成功的短请求当成模型准入，而是把“响应能完成”和“领域任务能安全发布”
> 分开。通过显式评测作用域复用既有 Agent/RAG/Harness，使用全新的 oracle-blind held-out
> 考卷，并把低思考档的预算、终态和失败收口固定在不可升权的边界内。
