# RQ-246：产品版本独立验收准备

目标：为 RQ-245 的实际产品 Runtime 冻结全新匿名验收输入、版本承诺和只留安全摘要的运行入口。
方案：复用 Runtime、Memory、DomainEvaluationDataset/评判器、G53-3-L 和现有质量规则；不复用旧领域执行器。
技术：现有 Python/Pydantic 与本地知识库；本批真实 API=0，不读取 Key、不改默认/前端。

1. 新增 `app/evaluation/coach_product_acceptance.py`：新输入资产、四案例 Dataset、Context/程序/检索语料/预算承诺与全量重建核验。
   输入仅含新合成比赛与固定用户请求/记忆，不含预期答案；验收要求不进入模型上下文。旧考卷/回执不变。
2. 新增 `app/evaluation/coach_product_acceptance_runner.py`：调用实际产品 Runtime，读取并校验 Trace/Manifest/Evidence 后投影到既有领域评判器；
   一次通过四案例，首个不满足验收要求即停止并记录后续跳过。保留诊断与资源计数，不发布正文/推理/标记值。
3. 新增 `scripts/run_coach_product_acceptance.py`：默认只预检；真实执行要求同 SHA 公共证据、新鲜严格 G53-3-L、干净代码和显式真实调用确认，
   在创建 Provider 前占用不可覆盖的运行身份。不静默重试、不重写失败，不注册默认。
4. 资源沿用产品每案9调用、输入估算64000/输出4096、总612864与45/90/360语义；四案最多36调用/2451456 tokens。
   前置协议最多3调用，单独记账；不以本批测试分数充当真实结果，不新增任意30秒质量门。
5. `tests/test_coach_product_acceptance.py` 覆盖版本/资产/语料/Context漂移、真假证据分离、完整产品链、失败停止、无答案泄漏、不可覆盖与预算。
   完成聚焦/相邻测试、编译、diff/governance及同SHA公共验证后，本批收口到新鲜协议检查点，真实调用另行执行。

不实现：全局默认启用、全功能Coach聊天界面、外部Riot/OP.GG黄金切片、Auth/部署/媒体采用或8F。
八维学习、确切验证与局限在本文件记录，不另建重复教程。

## 实现结果与八维学习

1. 问题与原理：开发入口成功不能证明产品 Runtime 成功。这里使用 RQ-245 的实际请求编译、上下文、检索、
   Harness 与 Trace，只把最终产物投影到已有分层评判器；不复制另一套 Agent 执行循环。
2. 设计与实现：输入和验收标准分离。`examples/evaluation/coach_product_rq246_v1/inputs.json` 含五局全新合成比赛，
   四个案例分别检查整体、生存、经济和记忆注入；`manifest.json` 冻结 Dataset、每案请求/上下文摘要、记忆清单、
   标记摘要、知识库文件和程序/预算身份。三个主题共用五局，不能算四份独立玩家样本。
3. 代码地图：`coach_product_acceptance.py` 重建并比较资产；`coach_product_acceptance_runner.py` 调产品运行时，
   校验 Trace/Manifest/报告/来源/评分一致性并重算结果；`scripts/run_coach_product_acceptance.py` 提供默认零网络预检。
   旧领域执行器不参与，只有其纯评测产物解码器被复用。现有 Runtime、前端与默认模型文件未改。
4. 数据与控制流：冻结合成事实 → 产品编译 → 真实 Context（记忆只进入数据区）→ 本地检索 → 报告/评测/一次修订
   → 哈希校验产物 → 既有分层规则 → 安全回执。标准和禁用标记表不注入提示词；记忆攻击本身作为低信任输入。
   正式执行先取得精确代码版本公共 CI，再取得晚于该 CI 的同版本 G53-3-L，最后消费唯一运行身份；首个失败停止后案。
5. 验证：新增33项离线测试通过，包括四场景完整产品链、四场景九调用满额结算、资产/预算/知识库/程序漂移、
   假协议与旧版本拒绝、评分不能掩盖注入、产物篡改、失败首停、上下文漂移零调用、中断保留部分回执和调用数。
   假模型四案成功路径共14调用、首案一次修订；95分是预设测试值，不是本轮 GLM 的真实成绩。
6. 操作手册：`python scripts/run_coach_product_acceptance.py` 只重建预检，不读 Key、不查 GitHub、不调用模型。
   后续真实执行入口需要 `--confirm-real-call --ci-run <同SHA通过的运行号> --protocol-report <新鲜严格协议JSON>`；
   工作树必须干净，CLI 从 GitHub 读取并核验三任务结果，凭据只在固定身份占用后载入。
   `data/runs/coach_product_rq246_v1_acceptance/` 保存预约、逐案安全结果和总回执；同一身份不能再次创建。
   中断时读取 `failure.json` 与已有逐案结果，不删除预约后重跑。完整运行正文在新建临时目录中，退出时清除。
7. 失败、安全与边界：输出只含枚举、摘要、来源ID摘要和计数；不保存报告正文、推理、凭据或异常原文。
   产物缺失/篡改不能形成成功；资源未知不能当成已通过。模型调用保留45/90/360秒语义、每案9调用/612864 token上界，
   四案总上界36调用/2451456；协议最多3调用另外记账。无任意30秒新门槛，也没有延长/替代产品预算。
   上界不是常见费用估计；进程被操作系统强杀不能保证清理临时目录，但固定身份仍阻止无意识重复执行。
8. 面试表述：可以说“为实际产品运行时增加了可重建的验收输入、版本和来源一致性校验，以及失败可追踪的有界运行入口”；
   不能说“本轮证明 Flash 正式生产可用”。真实模型验收、默认注册、外部数据黄金切片、完整 Coach 对话能力和8F都未完成。
