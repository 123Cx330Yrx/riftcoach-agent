# 编辑地址与语义消费：零付费方案裁决

2026-10-14，核查基线 `ba5922e4d7e39831e1ed2d427a467eae02030c42`。
本包目标是判断上次失败是否支持改地址协议，或需要改变编辑内容的生成机制。
不重新审判历史意见，不组装修补后的真实失败响应，不产生新模型请求或业务Host任务。

## 决定

保留现有 `block_N` 严格接收合同作为开发防线，**不选择新的编辑协议候选，不进入新付费准备**。
这不是认定当前编辑器可靠：本次真实链仍失败，正确初审到正确改稿的业务目标未完成。
已排除“只换地址表示就能解决本次问题”作为充分修法；没有证据把数组旧合同的局部成功
外推为当前互补链成功，也不能从一次裸键偏离断言模型内部成因。

## 可选方案与证据

| 方案 | 实际能力与反证 | 取舍 |
|---|---|---|
| 继续严格 `block_N` | 显式段落加段内唯一锚点，支持跨段重复原文、单次超过8段、原稿坐标原子组装；真实裸键被拒 | 保留防线，不据此宣布生成可靠 |
| 回退四字段数组 `block/before/after/reason` | 旧合同已有真实修订与正确保持，也已有缺required block的真实失败；同样只能验证地址与结构 | 不新增重复适配器，不作为语义修法 |
| 自动把 `14` 补为 `block_14` | 改变已发送合同的验收，且不会消除“两口径各仅2局”的错误 | 拒绝，不转换原响应 |
| 删除段号、全文唯一锚点 | 相同句子出现在两段时不能指定第二处；既有反例已证明表达力损失 | 不采用 |
| 每段一个工具或增加来源ID | 前者受8个tool calls限制；后者验证引用存在不证明替换断言有据，旧source_ids合同也曾缺字段 | 不采用为充分修法 |
| 强制远端schema或再加同义提醒 | 既有能力审计未取得可用的远端strict合同；本次原请求已经明确要求键名 | 不猜参数、不原样重买 |

依据：`2026-10-09-editor-protocol-audit.md`、`2026-10-09-full15-resumption-candidate.md`、
`2026-10-01-review-bound-edit-result.md` 和 `2026-10-14-review-duty-chain-result.md`。
选定历史调用并非随机样本，不计算或比较可靠率。之前提出的“数组合同能保留锚点就做适配”
条件不足：工程可表达性已有证据，重复实现不能回答新增的语义问题，故本包不实施该适配。

## 实际数据与控制边界

`review_duty_composition.edit_request` 把两份完整原样意见及来源交给现有编辑器；
`report_block_keyed_editor.inspect_exchange` 核精确请求/回执、模型、工具通道、段落、锚点、
重叠、章节、引用有效性和策略回声后才返回实际新稿。journal明确保留
`semantic_approval=false`，地址成功不意味着文字正确。

`review_duty_execution` 随后把原稿、实际新稿、编辑原响应和双意见交给独立编辑验收。
`review_duty_host_gate.Decision` 要求四项ReportAssessment：事实来源正确、正确内容保留、
身份目标保留、真实错误修正，且绑定实际新稿SHA和作者。任一编辑裁决拒绝返回
`edit_rejected`，不发送两次fresh；验收通过后两次fresh才从实际新稿重建完整来源请求。
这些是开发Host门，不能移除人工后宣称产品已具备自动语义保证。

现有 `audit_correction_consumption.py` 已用明确标为人工编写的离线反例证明：错误数字、
无据因果、全称扩展与空编辑都可能通过结构组装。加source_ids并不能拦截这些错误。
现有测试也覆盖格式合法的新事实错误由脚本化fresh拒绝；脚本化判定只验证控制流，
不证明真实GLM或Host必然识别。无需为同一边界再造一个编译器或镜像测试。

## 验证与后续

相称检查复用两个编辑合同、互补意见组装及执行停止分支的现有测试，另跑项目治理和
`git diff --check`；准确结果记录在活动progress。本包只改决策与当前状态文档，
运行源码、历史包和真实回执保持原字节，没有新授权、run、模型调用或Host业务任务。

下一技术工作应针对**替换内容如何保持来源限定**，先写出能区分候选机制的输入/输出
对照和反证，而非再改字段。任何候选须说明相较现有完整来源与正确意见新增了什么机制，
同时保留修复正文与摘要、同段多问题、跨段重复锚点、正确保持、样本/因果区分和真实成稿
fresh的能力；若只是同义提示、schema变形或已知单例答案，不进入新付费准备。
本包没有发现已被证据支持的生成修复，不以未选机制申请授权；automation保持PAUSED。
