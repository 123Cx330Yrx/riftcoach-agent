# 实际命题与直接修法：下一机制检查准备

目标是减少正确教练分析被扩义误报、真错修法遗漏直接影响的情况，继续为同版本完整15与真实
Agent消费准备质量证据。前两项误报的解释已找到正确统计，却选错原文命题；现有完整政策及
扩展示例已经明确全文消歧，因此不再继续叠同义规则，也不把源码中有规则当作模型会执行。

后四例能检出并单处修复未来外推、观摩归属、官方日期、标题能力证明，说明完整来源和既有
block-keyed编辑可以保留。这些正证据不撤销旧claim-scope:4误报、scope:3 fresh误报或scope:4
摘要/正文修法分歧。旧短教学同样没有让完整15全部通过，不能认定扩展示例或中转就是根因。

## 已准备的免费对照

`scripts/prepare_document_semantic_options.py`只读公开seal，create-only生成
[`document_semantic_options_preparation_20261011.json`](../../data/evaluation/results/document_semantic_options_preparation_20261011.json)。
三种教学组织各有精确policy文本和摘要；逐请求断言业务规则前缀、完整报告/来源消息、工具
schema、输出字段、模型、时限及其余metadata完全相同。只替换教学后缀，不增加调用或逐段账本。

| 对照 | 改变及目的 |
|---|---|
| expanded_examples | 原实际扩展示例；基准保留，不能因旧失败抹去其正证据 |
| short_examples | 恢复既有四个短例，仅比较教学长度/覆盖变化，不宣称已选择修复 |
| decision_sequence | 用“实际命题→全文范围依据→来源冲突/行动歧义→直接修法”顺序替换扩展示例；不输出思考过程、不增加字段 |

| 固定材料 | 检查的区别 |
|---|---|
| claim-scope:4 initial | 全样本后文已消歧，不能用中单另一组数字新增早死误报；其他实际真错仍须检出 |
| scope:3 final | 正确修后稿的泛指不能补成全部指标；可读性不变成fact_error |
| scope:4 initial | 明确中单错标仍须修；摘要与正文直接影响不能因数字表正确而忽略，既有Host分歧保留 |
| observed:3 final | 正确身份修后稿应通过，知识/外部来源条件观摩及样本观察保留 |
| observed:5 initial | 标题明确能力证明必须拒绝，正文限制不能撤销其独立真错 |

材料来自实际公开请求，保留完整输入。案例名及判据只在准备/Host侧，不注入Provider消息。
这些是已见开发反例和正例，不是独立holdout，不以5例或历史成功拼完整15资格。

主审与独立工程均在禁network/Provider、禁run读取条件下精确复建公开准备；独立另核无
凭据读取、Windows原字节相等、5个原expanded完整请求重建及15后缀变体的恒等断言。
工程证据见[收尾原生终答](../../data/evaluation/results/document_remaining4_close_engineering_review_20261011.json)，
仅证明静态构造，未判断新变体真实语义效果。

## 结果如何改变决定

若顺序变体仍把正确泛指补成全称，或借正文限定放过标题明确真错，则否定其作为共同修复的
充分性。若任一变体只能改善字数、协议或分数而没有同时保留正例和真错/直接影响覆盖，就不选它。
若短教学与顺序变体表现不同，才进一步区分组织顺序与示例负担；单次差异仍不能推出因果或稳定率。
摘要修法存在实质分歧时原样记录，不反复审查求一致，不把其标签传给下一请求。

当前产物是可重建的静态对照，不是运行候选。constructed_request_sha256是canonical JSON摘要，
不能冒充实际issued原字节SHA；继承的旧metadata只为对照保留，没有为新变体定义可发送身份。
下一步是把确有决策价值的比较接入隔离身份与完整请求/预算/原生双审接缝，形成具体调用规模、
停止分支和成本方案后才安排必要实测。当前Provider0，不另开付费批、不放宽业务门或默认入口。

正式同版本15、自然生成/工具/审查修订真实消费、8E、Coach/Training/四块联动、
Worker-DB-API-UI-journal、前端审美头像、Memory、身份运维、两树整合与八维学习依赖保持。
