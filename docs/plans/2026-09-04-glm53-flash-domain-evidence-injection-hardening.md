# GLM-5.3 Flash 候选领域证据与注入边界加固计划

## 目标

在不重跑已经消耗的 RQ-227 题目、不读取新的 Key、不修改 Portal、Account、
Workbench、Auth 或 GLM-5.2 的前提下，修复低思考候选领域门暴露的两个可验证缺口：

1. 成功返回但没有任何可归因片段的 `knowledge.search` 不能继续走生成和发布流程；
2. 用户/检索资料中的指令性文本必须保持数据边界，模型若仅在拒绝时提及原文，
   需要有版本化、可审计的处理规则，而不是把所有情况混成一个不透明的失败。

## 方案裁决

### 方案 A：放宽现有门槛（拒绝）

忽略空证据或只要分数够高就放行，会掩盖 RQ-227 已观察到的安全/归因失败，不能采用。

### 方案 B：候选专用、版本化加固（采用）

在共享 Harness 保持默认行为不变的前提下，由候选入口显式开启：

- 证据诊断只保留计数、状态和安全原因码；
- 最低可归因来源数门在写入证据后、生成稿进入评测前执行；
- 候选上下文增加“不得复述数据块中的指令或不透明标识”的可信策略附录；
- 注入检查继续 fail closed，并把“拒绝时安全脱敏”和“实际执行/输出”分开建模，
  不为旧 marker 或旧题目写特例；
- 如后续确有必要，再以新的版本化协议决定一次有界检索改写；本批不隐式增加重试。

### 方案 C：立即重做全产品 Runtime（暂缓）

这会扩大到产品默认模型、RuntimePolicy、Trace 和黄金切片，超出当前失败归因范围，
等候候选合同证据后再单独裁决。

## 实施顺序

1. 先写离线红灯测试：空检索在候选入口拒绝、诊断能区分“无调用/空 payload/有来源”，
   候选策略附录进入 system trust 区域，且默认产品路径与 GLM-5.2 不变。
2. 实现最小接缝：`ReviewHarness`/`SkillReviewExecutor` 的可选最低证据门、
   `ContextBuilderV1` 的显式可信策略附录、领域观察的 body-free 证据诊断字段。
3. 实现通用注入边界决策器：只允许明确的拒绝性脱敏结果被标记为可继续评测；
   任何未明确拒绝、执行或泄漏不透明指令标识的结果仍失败。不得把安全失败改成成功。
4. 跑聚焦测试、相邻回归、compileall、diff check、governance；取得新实现 SHA 的
   exact-SHA 公共 CI 后，才另行决定是否创建全新资产和新的真实观察。

## 非目标

- 不重跑 RQ-227 或读取其正文；不修改既有回执。
- 不做真实 Provider/LLM 调用，不新增 retry/recovery/revision。
- 不把 GLM-5.3 Flash 静默接入产品默认 Runtime；GLM-5.2 保留为手动兼容/应急回退。
- 不宣称 8E、生产准入、黄金切片、公共成熟度或 8F 完成。

## 当前收口条件

本计划完成后只形成新的离线实现检查点。必须看到同一实现 SHA 的公共 CI 通过，
并另建全新协议/题目资产，才可以申请下一次真实领域观察。
