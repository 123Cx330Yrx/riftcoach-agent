# 8E Portal Motion Method Fault Split（2026-08-28）

状态：`method-review / no-new-paid-call`。

这份文档回答一个关键问题：v4 很差，究竟是 prompt 写错、模式控制不够，还是模型能力不够。结论不能靠
“再换一个模型”得出，必须把已经发生的样本按控制变量拆开。

## 1. 先用大白话说明

我们要的不是“画面里出现几个会闪的东西”，而是确认母图本身像一幅活的海克斯场景：左 Rift、中央水晶、
右侧星图和近/中/远景环境从第一帧就一起动，中央偶尔有轻柔的纵向呼吸，但建筑、道路和平台不能被重绘。

v4 使用的是“单张静态首帧 → 整段视频”。这种模式只收到一张图和一段文字，没有真正的区域遮罩或中间帧，
模型必须自己猜“哪些地方怎么动”。它最终选择了最容易制造差异的中央平台圆顶，所以“源图保持得不错”和
“运动分配错了”可以同时成立。

## 2. 已有证据的同口径比较

## 3. v4 prompt 的自我归因

这次不是随机乱写，但确实写错了控制方式：

1. `platform response`、`breathing`、`fluid depth` 是抽象结果词，无法告诉模型具体改变哪一块已有材质。
2. “平台几何不可变”与“平台响应”在正向语义上竞争，模型用大圆顶完成了后者，negative 没能抵消。
3. “所有层同时运动”没有对应的区域/时间输入，单帧模式只能挑中央显著物作为运动出口。
4. 12 秒和 4.5–7 秒事件把注意力推向一个中心事件；它没有为左/右/near/mid/far 增加实际控制自由度。
5. 长正向说明加大量禁止项，让模型先守住构图，再用一个显眼的局部变化交差；继续堆形容词不会修复这个问题。

因此 fault split 的暂时结论是：**prompt 有责任，首帧模式也有结构性控制缺口；模型上限仍 unknown。** v4 不是
“模型完全不会做视频”的证据，但足以证明同类首帧请求不应继续盲抽。

## 4. 三条路线的取舍

### A：首帧单锚点 I2V

- 优点：母图身份和固定构图最容易保住，调用接缝已经验证。
- 缺点：没有真实区域/时间控制；v3/v4 连续出现中心独演、右侧静止和环境不动。
- 裁决：暂停。除非以后能提供多关键帧或明确 mask 输入，否则不再作为下一付费实验。

### B：真实视频编辑 + 时间/区域控制

- 形态：使用已有成功视频作为 temporal anchor，母图作为 geometry/material anchor；在 `00:00 / 00:04 /
  00:07` 三个时间点分别标出完整左/中/右区域和环境定位。
- 必须修正：中央只标水晶内部与现有光柱，不标整个平台；“平台 response”改成既有环面反射轻微起伏；
  左侧写宽幅流体层，右侧写星尘/节点/地形材质的持续相位变化，不写抽象的“能量连接”。
- 风险：即梦上次 Smart Edit 有 source drift 和 seam fail；它仍是最值得一次验证的路线，但必须先做更窄的
  source/mask contract，不能原样复制 v7。

### C：锁母图的混合材质制片

- 形态：母图永远是结构底；对 Rift 内部、道路流、云/空气、右侧星尘/地形、地面反射分别做低频纹理位移、
  遮罩内亮度/折射和错相视差。禁止用直线、圆环、节点网络或 HUD 作为主运动。
- 优点：几何、遮挡、颜色和 loop clock 可控，最适合做可靠的 Portal fallback。
- 风险：C-line 证明“机械线条叠加”很廉价；如果改成真实纹理/位移仍显贴纸，就应停止而不是继续堆 shader。
- 资产策略：Image2/Photoshop 只在需要一张同构材质/遮挡辅助图时使用，不重画母图，不把概念图放进 runtime。

## 5. 当前推荐的执行顺序

1. 先冻结 B 的窄版三时间点 mask/prompt contract：每个区域必须有具体运动载体；中心禁止平台体积变化；
   baseline 从首帧到末帧持续；事件只为中央水晶纵向呼吸。
2. 做本地 no-cost preflight：字符数、三帧说明绑定、source SHA、上传角色、音频、时长/比例、唯一调用路径；
   不先生成、不再用 Image2 做无关审美稿。
3. 如果 B 的实际模式不能表达区域/时间控制，或再次只靠局部亮斑制造变化，则停止生成式首帧循环，进入 C 的
   **纹理/位移型** proof；不把旧 C-line 线条 proof 重新包装成成功。
4. 只有 B/C 的一个候选同时通过人工“整幕持续、不是贴层”和 source/seam/codec 门，才讨论 runtime；当前
   production media 仍为 `0`。

## 6. 暂停线

本轮不再付费调用、不切到另一个模型、不把 v4 接入 runtime。下一次付费实验必须绑定这份 method fault split
和新的 B contract；失败时继续按 local → request → transport → output quality → method 五层归因。
