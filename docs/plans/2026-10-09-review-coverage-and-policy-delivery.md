## 两处实际命题与来源

`attribution:1` 原句为“混合位置均值受辅助局强烈拉低，应按位置分开解读”。
模型将“未限定指标”解释为与视野方向冲突；主审认为全文没有“所有指标”，指标明确化
可作 advisory，独立旧意见接受该 issue。完整来源中中单视野均值33.75、全样本45，
这反驳“所有指标都拉低”，却不能单独证明原文确实断言了全称。
未来执行须给出被否定的实际命题及全文依据，不能替原文补一个全称。

同稿 block14“全样本补刀与伤害差距主要来自辅助局拉低”则是明确真错。
从五局原始数值用 Decimal 重算：伤害胜败差全样本695.418333…，仅中单仍669.235；
构成变化只改变26.183333…，约3.765%。不能把伤害差距主要归于辅助局。
补刀中单胜8.805/败9.01，全样本胜8.805/败6.453333…，原展示8.8/6.45只是舍入。
这些统计分解不是因果估计，后续必须保持这一边界。

`scope:3` 原稿明确“中单口径…早期死亡几乎相同”。真实中单胜(3+2)/2=2.5、
败(0+1)/2=0.5，原句确实错误；后文全样本败(7+0+1)/3≈2.67、胜2.5的比较正确。
模型检错和修正数字正确，争议只在建议修法“本样本中更少的早期死亡并未带来中单胜利”。
最窄观测读法有来源；若读成反事实或零因果效应则没有来源。既有独立校准解释承认此区别，
但九控制中的 C06 仍分歧。保留意见，不加“带来”词表门，也不改旧失败标签。
影响结论的实质歧义仍可拒绝，但需要说明具体含义和依据，不能把措辞建议当事实冲突。

## 工程改动与反证

旧 Host task 常以“按既有全文标准”指代 policy，没有显式附上完整原文。
这证明交付不完整，不能证明历史审查者从未读过规则。Provider 请求中的完整规则一直存在。
九控制提供完整规则后仍有 C06 分歧，已经否定“只补传规则即可充分解决语义问题”的假设。

新增 `scripts/document_review_host_task.py` 作为前瞻任务入口：

- 先复用现有活动阶段/来源/receipt 验证，再核原始 request 字节 SHA。
- 初评/final 携带实际请求的完整 system policy；编辑同时携带初评和编辑两份原 policy。
- 原生六字段 binding 和 task 输出包络不变；Provider 的工具与 JSON 合同明确仅为被审材料。
- 全文核所有问题、解释、修法、advisories 和保留内容；接受报告时四项报告条件必须全真。
- 关闭批、关闭阶段、错 request 或变化的 receipt prefix 均拒绝。入口仅产任务，不调用或签署。

旧 helper 属于旧冻结源码集合，直接改写会破坏历史严格回放。因此新增入口，保留旧构建器。
新入口尚未被真实开放阶段消费；后续新计划须显式接入并冻结它，不能称默认运行路径已更新。
独立代码复核发现报告接受条件未写明，已补齐；既有导入门始终保留，没有放宽质量标准。
