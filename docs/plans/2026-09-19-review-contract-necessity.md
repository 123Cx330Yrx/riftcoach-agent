### 撤回唯一四中单解释的过强认定

实际正例不是一句脱离上下文的“四中单比较”题：

- block3 开头是近5局，结尾也说样本仅5局；内部明确区分4场中单和1场辅助，并给出4中单经济/伤害比较。
- 原风险 bullet 的局部定义被案例 assembler 替换，block9 实际是独立泛称标题 `## 所选比赛观察`。
- block10 只有“经济和伤害是较稳定的差异项。”，没有“上述四场中单”“同位置”等唯一回指。
- 后续 block13 是2胜/3负混合表格，block14同时给混合解释及中单对照。
- 原生已接受 c008 的 `context` 明确指向 block9，`scope_anchor` 为“所选”，解释实际逐行核对两胜与三负。它没有伪称这五场都是中单。数值关系本身成立。

因此，四中单是有力读法，五场所选样本也有文本依据。仅因执行方更偏好前者，不能把后者自动判为业务错误。开发数据的 accept 标签不能再无记录扩张为“必须唯一选 MIDDLE”的新 oracle；目录中算术方向相同也不能反过来证明任何明确换组都合法。

本次对正例已接受的13条 claim、对应补丁/复核解释及全文进行了直接复核，没有核实到另一个独立、无争议的算术/事实错误。这个结论范围有限，不等于全面生产质量认证。输入明确是ShowMaker观摩，报告仍出现“自身4局”“你的手感”等措辞，存在阅读者/观摩对象边界的产品表达风险；应按已有身份政策检查和清理，不能未经论证把它事后变成本 frozen pair 必败的新标签。

应保留真正明确的错误样本对照：原句显式说“四场中单”，评估却用包含辅助的五场并据此证明同位置结论，这仍是应拒绝的情况。修正的是此 frozen 正例的唯一指代断言，不是撤销样本/位置准确性的要求。

## 最小可复用方案：保留能力，替换表达

可以优先复用已有原生 Coach 评估、一次有界纠正、实际修订及复评接缝，而不是 Git 回滚到68e8670。v9 已证明直接事实可以合法携带来源边界；后来实际修复的来源类型、角色/训练意图、observed身份、实际queue_id、原始回执、确定性计算、预算与发布绑定都继续保留。

建议先形成一个独立、轻量合同候选，再决定是否替换当前 typed 实验：

1. **Host拥有事实编译。** 复用 `golden_review_source_catalog` 的真实地址/类型和 `golden_computed_evidence` 的确定性算术，保留完整原始输入、缺失、时间、位置、来源角色及hash。生成紧凑事实记录和真实来源句柄；计算不能替模型决定作者指哪组人，也不能把可见但未引用的事实自动当作已审证据。
2. **模型拥有业务判断。** 输入完整报告和来源；输出原生score/verdict/issues/passed_checks/summary，以及确有必要的原句/上下文/来源关联。把重点放在所有章节的事实、建议、身份、目标、位置、因果/长期断言、外部资料用途和前后矛盾。可以有轻量段落责任清单，但不能宣称清单本身证明语义完整。
3. **取消收益未证实的重复证明。** 不要求模型把正文标点全部放进quote区间，不要求普通来源每个数字都重述一套路径/format/places，不要求把知识/身份/版本事实塞进两类推断audit。编译的来源句柄要能验证类型和值；具体错误和高风险推断仍必须定位原句、说明证据关系。
4. **使用原生有限修复。** 一份完整有效评估可以结束；需要时最多一次有界纠正，完整保留原始意见和未解决问题。不能静默消失旧问题，也不能由Host编造pass或分数。需要报告修订时沿用一次修订并重新评估，所有调用继续计入同一预算。
5. **验证真实业务再接发布。** 在新候选中分别验证明确同位置替换、真实未来外推、普通事实错误、目标未知却强设训练、observed/self混淆、版本/OP.GG混用、实际queue误归属、错误标题、错误尾句及知识建议。保留本 ambiguous frozen pair 作语境讨论/兼容观察，不能独占验收，更不能改旧标签凑通过。

这不是直接删除现有校验然后接受旧JSON。当前 `ContextEvaluation` / `TypedReview` 及 Runtime adapter 有具体结构依赖；源地址编译后如何映射原生来源、保留来源类型边界、传给修订器和消费者，须做一个完整、可检验的新合同适配。没有实现和往返测试前只能称“有可复用接缝的方案”。

- 一对开发例不能证明一般漏检/误报率；原历史标题、因果和来源错配对照的未完成部分仍存在。

- 位置目标未知、observed身份、知识建议、OP.GG适用性和patch/date归属需要实际领域对照，不能只验证可序列化或地址存在。
