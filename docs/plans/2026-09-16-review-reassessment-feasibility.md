# 完整重评的离线可行性裁决

状态：比较候选首评真实失败，批次已停止；新临时首评合同仅完成离线修复与153项检查，真实语义未验证。
归属现有 ADR-0102，不注册新产品 Runtime。

要解决的是首评状态与第二步合法操作不匹配。旧补丁无法修复整段重复且最多改 16 条；
结构修复仍不能证明解释对象正确。当前 high、预算、完整上下文标准和 offline_only 保留。

比较三个实现形态：旧有有界补丁；每个原文 block 固定一份判断；完整重评但守住旧引用覆盖。
程序已有 SourceIndex，可继续负责来源定位。每 block 一份判断不能表达同段混合事实/推断；
进一步句子切分也不等于自动识别断言，因此不先建立另一套语言分句器。

离线原型用同一 FirstWire 描述首评和重评。完整结果允许重新组织 claim；程序按同一 audit、
同一 block 的字符区间核对：每条旧引用都由新引用的并集完全覆盖。合并重复、拆分大段和
更新全部条目都可行，截掉错误尾句、换源、清空原审查内容则拒绝。原始判断/说明保留审计。
这只证明文字覆盖，不证明重评真正处理了每个命题，后者必须保留独立反例和人工语义审查。

旧 issue 默认必须逐字保留；撤销或变更必须逐项提供有效证据编号和理由，原问题留在审计中。
high prompt injection 仍为终止，不可通过重评清掉。新增问题及最终判断继续过完整最终校验。
首评缺来源、缺块、缺标题、JSON 不完整等明确终止；不吞后缀或猜缺失判断。

完成条件：用可执行离线测试证明重复重组、超过 16 项更新、超过 16 标题以及 issue 保护，
核对实际 v10 回执和两份冻结完整报告的输入尺寸，并展示至少一个“结构通过仍语义错误”
反例。总预算继续实际用量结算，不制造五次最大预留之和的新门槛。原型若仅结构可行，
结果必须标为该层可行，不能解除真实入口；后续语义设计需要独立裁决。

## 本轮结果与选择

选择保留“完整重评＋字符区间覆盖＋显式问题处置”作为下一步离线原型，停止扩建旧补丁。
这不是选择其生产采用或恢复实测。`golden_reassessment_feasibility.py` 没有 Provider、
运行器、注册或在线开关；旧候选的 live hold 继续生效。

## 接续比较关系合同（已完成离线实现）

### 接续实现范围

本批将比较关系做成第二步完整重评的可核验输入/输出合同：程序从事实包生成
全体已纳入比赛及各位置的胜负分组，保留成员、指标、均值、逐行方向及缺失状态；
模型在 claim 内选择实际使用的 cohort/metric，继续用唯一 explanation 解释原文关系。
不增加另一份判定、解释复核字段或第三次评估调用。选择器不会自动证明作者所指对象，
错误选择、错误自然语言说明和遗漏比较仍必须由真实语义对照检查。

完成顺序：比较依据及绑定校验 → 同方向异样本/同数字异指标/标题/跨段/外推反例 →
完整请求预算测量 → 决定工作流接线及真实验证资格。现有失败入口保持 offline_only；
若离线发现方案仍有合同死路，先修完整设计，不修改旧回执或付费碰运气。

补齐“比较对象—证据—解释”的语义合同，再决定是否接入完整重评工作流：

1. 用本轮原始 c010 和已知标题错绑，明确语义验收检查的对象。原文引用和标题编号由
   程序负责；样本成员、分路、胜负组、指标和可复算值从确定来源生成。模型仍负责判断
   这些证据是否支持原文含义，不能把规则匹配或一个 source ID 称为语义证明。
2. 比较在第二步显式核对上述关系与当前自由说明的输入/输出成本，复用当前两步/五调用
   预算。不再堆一份独立的“解释复核说明”，也不增加模型调用来代替设计。
3. 把同方向但不同样本、同数字但不同指标、错误标题归属、跨段限定和真实未来外推一起
   用于离线合同检查。支持的正确观察应保留；反例应被识别或明确保留为必须人工验收的
   语义风险，不能靠消除说明或手改结果证明成功。
4. 只有整体方案能说明上述关系如何被审查、完整请求仍可执行，才接工作流并按原计划
   进行一次成对真实验证。这里没有新增用户审批要求，仍按既有授权执行。
