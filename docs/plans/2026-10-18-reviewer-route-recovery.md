# 审查路线：修复执行合同与更正裁决

2026-10-18。诊断分支 `codex/reviewer-route-diagnostics`；8E仍未完成，GLM产品采用决定不变。

## 本工作包与结束条件

用户要求从指定回复审查推进后，授权完成必要的下一系列工作。本包解决两个明确的软件/执行缺口：
完整请求的工具选择与接收要求不一致；失败观测及用量在语义判断前丢失。同时更正标签偏好被当作
业务失败的评判。完成条件是实际SDK/进程路径的断网验证、历史公开响应的确定性消费核对及恢复指针一致。
不以本地测试证明模型可靠，不新建付费包、不索取密钥、不重开旧批、不修改旧回执。

## 已采用的工程取舍

| 项目 | 处理 | 原因与限制 |
|---|---|---|
| 工具选择 | 新诊断模式 `nonstream-tool-v1` 明确选择 `submit_report_review` | 业务已经要求这个工具；保留auto却拒绝任何文字会使API允许的路径被业务必然拒收。明确选择仍不能保证第三方遵守。 |
| 响应接收 | 仍只接收一个完成的目标工具调用；reasoning可存在但不保存；文字/混合输出拒收 | 不从文字中抽JSON、不忽略额外拒绝、不修补模型参数以制造成功。 |
| 观测顺序 | 先计终态、输出类型/数量、工具候选数量，保存已知用量，再检查身份/终态/schema | `reported_completed`与验收分开；混合输出明确显示工具候选数，不能再从non_tool_output猜零工具。 |
| 观测内容 | 固定状态和计数；任意类型归other，不写正文、reasoning、模型自报任意文本或异常消息 | 失败原因不需要保存私有推理；未知仍为未知。 |
| 执行入口 | 复用 `reviewer_responses_process.run_once` 的create-only目录、stdin凭证、deadline/取消/回收 | 新模式需显式选择、显式proxy；旧批控制默认仍stream。无新付费CLI或自动重试。 |
| 业务校验 | 复用原请求绑定与 `review_duty_direct_patch.validate` | schema通过后仍检查verdict/issues、来源、修法覆盖；实际补丁组装继续走原preview。 |
| 提示 | 不追加r01/r02特制提示；原全文、来源与schema逐字保留 | v1的“数字正确不得报事实错”过宽，且含原题具体线索；不再带入未来诊断。旧提示原件不改。 |

数据路径：原业务请求 → 新非流式wire（显式工具）→ 现有独占子进程 → SDK → 无正文观测/计量
→ 工具schema → 原业务validator → 回执。`ok`、`business_validated`只描述相应层；语义、上游身份、
资格、发布仍未认证。16384输出/64000输入检查复用最近全文样本边界，单次300秒由父进程硬截止；
这不是任何付费授权或新总预算。

旧stream transport与旧原件不改。`scripts/reviewer_responses_nonstream_probe.py`是既有未跟踪旧稿，
保留原字节，本包不采用它。后续不能再从outputs复制full_sample.py作为事实上的新执行入口。

## 下一步的采用判断

**该第三方路线仍是未获资格的候选，现有证据不足以采用或宣布它优于GLM；也不再以other标签淘汰它。**
本地故障修复已具有明确价值，但不能回答端点遵守新工具选择及真实审查质量的问题。

下一项有效工作是重新确定有限语义筛选的判读材料与决策，而非继续r02-v2分类调试：

- 固定同一请求/传输版本，按完整来源判断问题、解释、修法及正确内容保留；类别差异只有在与含义
  矛盾或存在明确业务影响时才构成问题。算术正确不豁免主体、来源及建议依据错误。
- 正对照必须确无实质问题；发现新真错则材料前提失败，停止该设计，不把模型发现算误报。
- 调试过的r01/r02只能作开发回归，不能再称独立稳定性对照。不得把不同版本的局部成功拼成资格。
- 若未来需要真实请求，必须先有明确能改变采用决定的检查、固定成本上限及停止分支，沿用原
  授权/精确HEAD与CI/实际路径/独立审查要求；本包没有准备或开启新批次。

本地工作完成后不继续扩大传输框架；真实质量、同版本15例、自然Coach/Training、四块联动、
前端审美头像、Memory、身份运维、两树整合与学习仍按原依赖验收。没有推进主阶段或产品资格。
