# 5C-6：Skill Router 模型兜底采用决策

## 1. 要解决的真实问题

双 Skill Router 的 independent holdout v1 得到 11/12。唯一失败是：

```text
分析一下我最近键盘的表现
```

`recent-form-review` 需要“近期范围 + 复盘目标”。这句话同时命中“最近”和
“表现/分析”，又没有命中排除词，因此确定性 Router 按 Manifest 正确选中了近期
复盘。但“键盘”不是 LoL 对局，产品期望应当拒绝。

5C-6 不负责把这条题改到通过，而是回答：这个 Bad Case 是否足以证明现在需要
LLM Router fallback，以及其他方案是否更简单、更可靠。

## 2. 当前约束

- Router 只选 Skill，不执行 Skill、Tool、Harness 或模型生成任务；
- 排除信号是代码层硬否决，多候选命中必须返回歧义；
- holdout v1 已封存，不能根据失败增加“键盘”排除词或改写触发规则；
- GLM 是唯一真实 Provider，当前 Adapter 只声明 `text_chat`，没有端到端
  `structured_output` 能力；
- 当前只有一个维护者合成的域语义失败，不能代表生产分布；
- 阶段 5P 已规划类型化近期复盘 API；阶段 6 才扩展完整复盘/对话入口、会话上下文
  和用户澄清能力。

## 3. 底层原理

模型兜底并不是“规则没匹配就问模型”这么简单。这次错误已经是 `selected`；如果
模型只处理 `rejected/ambiguous`，它根本看不到这条错误。要捕获它，系统必须识别
哪些 selected 属于低领域证据，或者让模型复核所有 selected。

```text
确定性匹配
  ├─ 强领域证据 selected ──────────────> 保留
  ├─ 低领域证据 selected ──?──> 澄清或语义复核
  ├─ ambiguous ─────────────────────────> 澄清
  └─ rejected ──────────────────────────> 拒绝或有限兜底
```

因此，引入模型前仍然需要一个确定性的“何时调用模型”边界。否则每次路由都增加
延迟、成本和不确定性，并把 Provider 故障变成 Router 故障。

## 4. 方案比较

| 方案 | 收益 | 主要代价/风险 | 本次结论 |
|---|---|---|---|
| 给排除词加入“键盘”等设备词 | 可直接修复当前案例 | 开放世界黑名单无穷；直接污染 holdout | 拒绝 |
| 所有请求强制包含 LoL 专属词 | 确定、便宜、可解释 | “最近状态怎么样”等合法简写会被误拒绝 | 暂不采用 |
| 类型化入口 + 低上下文澄清 | 上下文可信、失败可见、无模型成本 | 需要 5P/6 的 API 或会话消费者 | 首选后续方向 |
| LLM 复核低领域证据 selected | 能理解“键盘”修饰“表现” | 先要定义低领域边界、结构化输出、超时、成本和新 Eval | 暂缓 |
| Embedding/分类器路由 | 可做语义相似度 | 当前数据量不足，阈值不可解释，新增模型资产 | 拒绝 |

## 5. 决策

阶段 5C V1 继续只使用 `DeterministicSkillRouter`，不实现 LLM fallback，也不根据
holdout v1 修改 Manifest 或 Router。

优先采用顺序为：

1. 阶段 5P 先用已规划的近期复盘类型化入口提供可信任务范围；
2. 阶段 6 的完整复盘/对话入口再覆盖其他任务范围，并对歧义或低上下文请求进行
   用户澄清；
3. 收集新的、与 holdout v1 隔离的生产式路由案例；
4. 只有重复出现多个独立语义失败族时，才建立模型语义复核实验。

“暂缓”不是永久拒绝。满足以下采用门槛后，可以重新打开 LLM fallback ADR：

- 新鲜数据中出现多个不同语义失败族，而非同一“键盘”案例的改写；
- 新建 development 与 independent holdout，不能复用 holdout v1 调参；
- Provider 端到端支持并测试结构化 `RouterDecision` 输出；
- 模型方案显著降低 false-selection，同时不破坏硬排除和歧义准确率；
- 记录 p50/p95 延迟、Token、调用成本、超时和不可用率；
- Provider 失败、非法输出或越界 Skill 名称时一律 fail closed；
- 模型只能在代码给定候选中提议，不能执行 Skill 或绕过权限合同。

## 6. 非功能需求

### 性能与成本

V1 Router 保持纯本地同步函数，不增加网络往返和 Token 成本。未来模型实验必须单独
统计路由调用延迟，不能混入报告生成耗时。

### 可靠性

Provider 超时、429、5xx、非法 JSON 或空响应不得变成静默选中。模型失败时返回
拒绝/澄清等安全终态，而不是猜测一个 Skill。

### 安全

用户表达是不可信输入。未来模型 Router 的 Prompt 只能包含最小候选元数据，输出
必须经过现有 `RouterDecision` 与候选白名单校验，不能把用户文本当工具或系统指令。

### 可维护性与可解释性

当前 Manifest 信号仍是可审计证据。若未来增加语义复核，Trace 必须同时保留确定性
证据、为什么触发模型、Prompt/Provider 版本、模型提议和代码最终决定。

## 7. 测试与验收边界

本检查点只做采用决策，不修改 Router 行为，因此验收证据是：

- holdout v1 原始结果和 Bad Case 分类保持不变；
- Router、Manifest 和 Provider 代码无修改；
- ADR 明确记录方案、成本、失败模式和重新采用门槛；
- Skill/Router 定向测试、完整回归、compileall、治理和 diff 检查继续通过。

本检查点不能声称：

- 已修复设备域假朋友；
- 已实现用户澄清；
- 已验证模型 Router；
- 已证明确定性 Router 适合生产中所有自然语言。

## 8. 面试安全表述

> 我先用独立保留集验证确定性 Skill Router，发现一个设备语义假朋友导致的错误
> 选择。由于只有单一合成 Bad Case，且当前 Provider 尚无端到端结构化路由输出，
> 我通过 ADR 暂缓 LLM fallback，保留零网络、可解释的确定性 V1；同时定义了类型化
> 上下文、澄清机制、新鲜数据集、延迟成本和 fail-closed 等重新采用门槛。
