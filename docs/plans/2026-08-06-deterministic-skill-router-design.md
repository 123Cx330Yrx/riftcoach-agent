# 阶段 5C-3：确定性 Skill Router V1

> **2026-08-06 边界更正：** 本设计当时把拒绝/歧义细节和版本化开发评测一起
> 纳入 5C-3 实现批次，实际分别提前覆盖了 5C-4 和 5C-5。代码可以保留，
> 但 5C-3 的独立完成范围只是确定性匹配策略；后两项仍须回到原检查点复核。

## 1. 本轮目标

5C-3 将 5C-2 Catalog 产生的候选与 5C-1 Router Contract 连接起来：

```text
用户表达 + SkillRouteCandidate 元组
→ 规范化文本
→ 对每个 Skill 计算声明式正负信号
→ selected / rejected / ambiguous
→ RouterDecision
```

Router 只选择工作流，不执行 Skill，不调用工具、模型或 Harness。

## 2. 方案比较

### 不采用：整句示例精确匹配

`positive_examples` 可以用于文档和评测，但用户只要增删“帮我”“一下”等词，整句匹配就会失败。把示例直接当规则会让 Router 看似确定，实际非常脆弱。

### 暂不采用：模糊相似度或向量路由

字符相似度、Embedding 或 LLM 可以覆盖更多表达，但需要有代表性的误路由数据来校准阈值。当前只有一个真实 Skill，此时引入分数会产生难以解释的假精度，也无法证明收益高于成本。

### 采用：Manifest 声明式信号组

每个 Skill 声明：

- 若干 `required_signal_groups`：每组至少命中一个短语；
- `excluded_signals`：任意一个命中就否决该 Skill；
- 正负完整示例继续用于说明和回归，不直接控制算法。

例如近期状态复盘需要同时出现“近期范围”和“分析目标”，因此“最近”本身不能触发，“状态”本身也不能触发；“分析最近十局状态”同时满足两组才成立。

## 3. 文本规范化

V1 对用户文本和配置信号使用相同的纯函数：

1. Unicode NFKC 规范化；
2. 英文字母大小写折叠；
3. 删除空白和标点，只保留字母与数字。

这样 `MATCH ID`、`match_id` 和全角字符可以得到一致比较结果。规范化不做分词、同义词推断或语义猜测；需要支持的同义表达必须由 Skill 明确声明。

## 4. 决策规则

对每个 Skill：

1. 每个必需组选择命中的最长信号，避免“最近”和“最近十局”重复计证据；
2. 收集所有命中的排除信号；
3. 所有必需组均命中且没有排除信号时，该 Skill 才是匹配候选。

最终：

```text
没有可用 Skill → rejected / no_available_skills
零个 Skill 匹配 → rejected / no_matching_skill
一个 Skill 匹配 → selected / matched_skill
多个 Skill 匹配 → ambiguous / multiple_skills_matched
```

结果不输出置信度。证据保留 Manifest 中的原始短语，方便 Trace 和测试读取。

## 5. 失败与安全边界

- 路由规则在 Skill 加载阶段校验，空组、重复组名和重叠信号直接拒绝；
- Router 不执行用户文本，也不把用户文本当系统指令；
- 排除信号只影响路由资格，不承担完整安全策略；
- 未支持请求必须明确拒绝，不能因为只有一个 Skill 就默认选中；
- 多个 Skill 同时成立时返回歧义，不使用候选顺序偷偷打破平局。

## 6. 提前实现的 5C-5 评测准备

本地工作树已提前建立版本化开发集，覆盖真实 `recent-form-review` 的正例、改写、
部分匹配、单局请求、版本请求、实时请求、域外请求与空 Catalog。该评测实现仍属
未验收的 5C-5 准备工作，不随 5C-3/5C-4 公开基线提交。

当前产品只有一个真实 Skill，因此产品基线不能真实产生歧义。多候选歧义使用合成 `SkillRouteCandidate` 做策略单测，并在结果中明确标注；不创建假的第二个业务 Skill，也不把开发集称为独立保留集。

只有未来真实多 Skill 评测出现稳定 Bad Case，才考虑模糊相似度或模型兜底。

本节描述的开发集是后续 5C-5 的准备工作，不是 5C-3 的完成条件，也不是独立
holdout。首批真实 Skill 的扩展时序须在进入 5C-5 收尾前单独裁决。

## 7. 本轮不做

- 不执行 Skill、Tool、AgentLoop 或 Harness；
- 不调用 LLM、Embedding 或外部 SDK；
- 不根据 Provider、成本或延迟选择模型；
- 不做用户澄清对话；
- 不添加第二个真实业务 Skill；
- 不宣称当前小型开发集证明了自然语言路由的泛化能力。
