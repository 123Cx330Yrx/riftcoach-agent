# 把诊断和十五例资格验收分开

用户2026-10-08指出当前逐例失败即停、修复后重启整十五例的推进过慢。问题成立：
诊断只能暴露首个问题，同时重复CI等待、Host签署和资格收尾；并非全部成本来自Provider。
本文件是离线方案，不构成新付费授权或对旧批停止条件的修改。

## 目标和实际接缝

每轮诊断获得十五个独立初评的失败分布和首次偏离，集中修复共同机制；仍需同版本完整
初评/必要编辑/fresh才能取得资格。诊断失败不得伪称合格，也不能拼旧版本成功数。

复用现有`run_document_review_diagnostic.py`的真实完整初评、transport、全文双审、原生事件
与只读封存。案例来自现有frozen_cases的原十五份input/report，不构造更容易的新样本。
建立独立诊断账本，不使用原15资格runner或伪造case-completed；初评返回真实issues和
advisories后审查质量，不把待修原稿的错误算成Host输出缺陷。

## 三层工作与结束条件

1. **成批初评诊断。** 先列全十五例的原件、期望边界和来源，再冻结完整请求。
   一例语义失败记入失败集合，继续下一个独立案例；不编辑、不fresh、不授资格。
   传输/身份/来源绑定/协议/预算/主体可用性异常仍立即停止；错误不能污染下一例或触发重试。
   初评质量的主/独立语义分歧单列，不把其中一方改成另一方来凑通过。
2. **集中修复与失败集合回归。** 先按实际主张/方向/量级/样本边界/建议分流归类，不按段号
   合并不同含义。核全部已知失败及其正确/真错对照；直接修明确软件缺陷，核旧方案反证。
   源码改变后原身份失效；缩小的回归只作诊断，不是十五例资格。沿用已有回放/原生审查，
   不为每个字段新建runner、教程、全量CI或新的审批问题。
3. **最后冻结资格。** 诊断显示选定机制值得整链验证后，再按一份新身份测试完整十五例。
   保留原质量门及初评→必要编辑→fresh、预算、真实全文双审、首失败停止，不借旧资格。
   只有同批15完整成功才可review-controls；自然产品消费另验。

诊断收集十五例最多15次GLM初评，比最坏整链35次少20次；它仍有成本，必须在完成
离线接线、独立复核、准确冻结及同提交CI后，按具体金额/时间上限取得新授权才运行。
先审查既有实际证据，若足以决定修法则不运行完整扫描。不能把最坏上限当实际预计账单，
不能为了少数新问题重复购买全部已知同条件诊断，也不能逐例申请权限拖慢用户。

这些是历史开发证据，跨批不累计资格。不得称后十一例已修好或全部编辑/fresh已验证。

对两个分歧分别明确实际断言、全文依据、来源支持或冲突、会影响哪项结论：
- attribution:1：泛指均值是否被扩写为所有指标；独立的伤害主要归因真错继续保留。
- scope:3：建议修法的样本描述是否实际声称因果；明确零效应、未来全称反例继续拒绝。

### 三、集中开发验证，覆盖初评和必要尾链

样本从原十五例中按故障机制选，不按已知哪个容易通过选：

- 配入正确控制和明确真错控制，检查修复没有压制真实错误或新增误报。
- 覆盖尚未观察的编辑类型：范围/统计、未来外推、对象身份、来源日期、标题与正文。

以一份集中诊断计划运行。某例初评失败则停止该例尾链，某例编辑失败则不做该例

来源、意见与受影响路径确实适用才可用，并明确标作尾链诊断。若不适用就重新初评。
不能预先承诺复用，更不能直接续开旧批。所有新增调用逐项纳入具体冻结预算。

### 四、达到条件后，做同版本完整十五例

进入条件：两处已知失败有对应实证，正确控制保持、明确真错能检出且修正；代表性
编辑没有损坏正确内容，新稿fresh无实质误报漏检；不存在被当作“已修好”的裁决分歧；
身份/预算/审查路径及相关CI通过。若诊断有新失败，先按根因合并处理，再只重验受影响
集合及相邻正确/真错控制，不立即回到完整十五例。

满足后一次冻结候选并按原标准做完整十五例：同版本、全文双审、必要编辑与fresh、
首失败停止、不拼接历史成功数。模型仍有不确定性，诊断不能保证正式验收绝不失败；
它的目标是把可提前发现的问题集中暴露，减少从第一例重新发现问题的次数。
