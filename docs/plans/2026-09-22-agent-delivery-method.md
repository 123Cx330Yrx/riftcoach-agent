# RiftCoach 从目标到交付的执行方法

2026-09-22 系统修订。适用于当前 8E 及后续已授权项目推进；这是执行约定，不新增产品门槛或阶段。
用户要求的是改变实际做法、诊断和交付，不是增加复盘仪式。既有采用标准、模型、授权和产品范围优先。

## 0. 全周期执行，而非下一步承诺

本方法覆盖目标选择、方案决策、实施、诊断、验证、集成和交付。约束的是判断依据和结果，
不是固定技术路线。无法事先保证某方案“最正确”；选择应与当时证据匹配，遇到反证及时改变。
检查发生在新工作包、关键反证、真实接线或交付边界；不按每条命令、每轮对话重复走仪式。

| 决策时点 | 在现有工作卡或证据中留下什么 | 允许灵活调整什么 |
|---|---|---|
| 选目标与拆工作 | 玩家任务、当前主阻断、必要依赖和本包结束条件；查已有实现及置后需求 | 包的大小、实现顺序、独立工作安排；不自行改业务范围和阶段 |
| 选策略与投入 | 为何该机制能作用于故障、最强反证、最小区分性检查、结果对应的去留；有争议时比较真正可用的备选 | 技术方案可以替换；可表达/节省字符不足以批准完整实现或解释可靠性 |
| 实施与诊断 | 首次偏离的实际路径；同机制涉及哪些生产者、消费者及失败/恢复分支 | 明确缺陷直接修；跨层矛盾则重审合同，不强制永远小补丁或一律重构 |
| 验证与集成 | 原反例、应通过正例、相关边界和实际消费证据；区分本机/提交资料、替身/默认入口、离线/真实 | 只做能回答疑点的检查；关键假设只能实测时，沿用授权和预算安排必要实测 |
| 交付与恢复 | 消除的业务缺口、仍存限制、失败成本与未知项、下一动作及解锁的后续依赖 | 必要时调整路径；不能靠换版本重置失败历史或拼旧成功 |

在投入完整变体或新一批付费验证之前，检查是否已有更便宜的证据足以作决定，是否继续沿用
被否定的前提，以及复杂性、调试时间和调用成本是否只在增加而业务缺口未减少。
若连续修改只迁移报错、扩充协议或没有区分新解释，回到本工作包的方案层审查任务划分、
输入/输出负担和已有能力，而不是继续修最后一个字段。停止无信息重试，保留必要实测和独立推进。
新实验在工作卡写本批规模、硬上限和停止分支；不得借创建新候选绕过原预算或失败裁决。

验证前追踪改动的实际调用者和结果消费者；新增测试资料确认能从提交内容取得，不把本机
忽略目录当公共测试前提。有此类依赖疑点时用无本机资料的检查或已有禁止读取保护，
不为每次文档修改新建干净环境。对同一工作包批量提交和验证，避免一条小补丁一轮全套CI。

方法成效在下一次实际结果出现时核对：主阻断是否缩小、哪个决策因证据改变、同类遗漏是否复发、
是否增加了真实可用路径、花费是否获得了信息；不以文档/提交/测试数量自评有效。
关键反证或工作包交接时顺带查后续依赖表，恢复已解锁的Coach/Review/Training/Evidence、
前端审美及其他工作；这不是每轮重读全部历史。普通工程调整直接执行，用户授权边界照旧。

诊断只需能区分技术选择，产品验收才需要完整质量证据；两者不能互相冒充。

旧 task_plan 有 3596 行、canonical 有 5907 行，当前行动夹在历史排程里，机器“唯一下一步”仍是旧方案。
本次将原字节及 SHA256 归档至 `docs/archive/2026-09-22-execution-method/`，当前文件只保留活动状态、
依赖和追踪入口。归档不是新指令，不能恢复旧行动。既有阶段顺序和未完成需求均保留。

本次续查以abc695a为起点：原始失败保留、buffered充分修法被反例否定后停止，这些行为有改善；
但5c952ad测试依赖本机资料、用量修复起初漏实际整链、task_plan末尾仍指向ADR0105，说明约束
执行不完整。治理检查当时通过，不能发现这种语义过期。本次去掉末尾重复行动，只链接活动工作卡。
位置数组仍只是表示原型；把它直接排成完整实现属于过早承诺。本次将当前行动缩回最小合同反例
与方案裁决，模型生成可靠性另需实测，不能由离线往返推导。上述缺口是执行问题，不归咎于模型。

## 2. 目标、拆解与优先级

主目标始终是 Agent 围绕玩家需求完成教练任务：理解请求和身份、选择工具/知识、结合上下文、
形成分析与行动、核验来源、持久化并在界面交付、接收反馈继续调整。
当前 ShowMaker 观摩切片只能证明其实际覆盖的链路，不能代替自然 Coach、本人 Training 或全阶段验收。

每个有独立业务结果的工作包，在活动计划写一张短工作卡；常规命令、单个测试、明显修错不拆卡。
目标不能写成“优化、继续研究、通过测试”，要写出触发输入、期望行为、现在与完成后的差异。

| 工作卡字段 | 必须说明的实质 |
|---|---|
| 目标与依据 | 对哪个玩家任务/当前阶段阻断有帮助；来自用户决定、业务合同还是执行假设 |
| 起点与差距 | 当前实现/证据、尚未证明的部分；旧成功不能拼成新版本已完成 |
| 实现路径 | 实际入口、数据/控制流、受影响文件；复用什么、改哪个机制；必要备选及取舍 |
| 依赖与边界 | 哪项必须先完成，哪项可独立推进；成本授权、回滚点及不变的业务约束 |
| 交付与验收 | 可检查的代码/行为/结果；需要哪种证据，失败如何被发现 |
| 诊断或失败分支 | 核心假设、能推翻它的观察；结果如何决定继续、修复、换方法 |
| 当前状态与下一动作 | 只写一项活动工作和具体下一动作；阻断、风险与后续依赖单列 |

优先级按对主阻断的作用和信息增量决定，不按“容易修”“测试多”“刚发现”决定。
已暴露的数据破坏/越权等真实紧急问题优先处置；一般潜在缺口在影响它的接线/发布前处理，
不成为诊断其他问题的万能前置。独立产品工作可并行或顺序推进，但必须说明业务收益，不能绕开难题制造进展。
只细化当前可执行工作与近端依赖，远期保留交付、入口和触发条件，不提前制定几百个固定步骤。

## 3. 实现前后怎样保证实现的是目标

从用户入口沿真实调用链读受影响代码、合同和现有测试，区分运行代码、诊断脚本和 scripted/fake 路径。
先确认需求是否已实现，避免重写已有 Runtime、事务或存储；不能因测试可注入就宣称默认产品已接线。
选择能解决机制的最简单方案，而非字符最少的补丁。必要的结构调整可以做，不要求永远局部修补。
新增抽象、协议或依赖必须对应旧方案无法满足的具体要求，并说明替换掉什么复杂性；不能默认层层叠加。

实现与验证围绕同一个工作包推进。明确可复现的软件缺陷直接修复并做相关回归，不先举办大复盘。
行为复杂或涉及真实模型时先用最小原型、已有反例检验关键假设，失败就修改设计，不先铺满周边设施。
代码完成后检查实际接线与错误路径、取消/恢复和结果消费；只覆盖变更相关部分，不对每步重做整站检查。
成功接线也不解除模型质量门。能够单独验证的接线提前完成，但明确模拟与真实证据的边界。

## 4. 故障诊断：从现象走到可验证的机制

诊断的深度以能可靠决定修法为准，不以报告长度为准，也不要求解释所有未知原因后才能修一个明确缺陷。
对同类反复失败，停止原样重试，在现有 findings/失败审计内维护一份问题记录，不另起一套研究框架。

1. 固定失败事实：实际输入、输出、版本、来源、回执、时序、预算及真实症状。保护原始证据；
   分开模型公开输出与私有推理，未知费用照实标记，不补写一次不存在的通过。
2. 验证预期：回看用户采用标准和完整业务上下文，检查数据、标签、测试/校验器自身是否错。
   人工判断也可被新证据推翻；不能为了保住旧标签认定模型必错，更不能悄悄降标准让它通过。
3. 沿数据流定位：请求/身份 → 来源/工具 → 模型 → 解析/验证 → 修订/复评 → 发布/消费。
   找到首次偏离期望的位置，列出其他故障是否独立；不要只追最后抛出的异常。
4. 提出少量真正竞争的解释。每个解释写支持/反对证据、待观察差异和结果决策，不堆泛泛猜测。
   “字段缺失”“输出耗尽”“泛指被读成全称”是现象；根因需有机制、复现或有区分力的干预证据。
5. 选择最省成本且足以区分解释的检查。确定性回放优先；需要模型实测时在已有授权/预算内直接安排。
   不以“省调用”为理由永久拒绝必要实测，也不以“深度诊断”为理由全文重读所有历史。
6. 尽量固定来源、报告和其他条件；同时改多项时明确混杂因素。单例说明该例，配对显示差异；
   没有隔离变量不能宣称因果，没有有依据的重复/代表性设计不能宣称稳定率。
7. 结果出来立即更新判断和决策：反证出现就撤回假设，不继续为原修法辩护。若各结果都只导向
   “再改一句提示”，该检查的决策价值不足，应换检查或承认当前证据无法选择方案。

问题记录只需这些信息：症状与影响、证据位置、已排除/未排除解释、机制假设、最小干预、
预期/反证、实际结果、选定修法、遗留限制。已有材料引用即可，不抄长回执。
已证实软件缺陷与尚未知的模型语义成因分开处理；不能用修好前者宣称后者解决。

## 5. 修复、测试与完成判定

修复应覆盖同一机制导致的问题族，而非只对已知句子、数字或案例 ID 特判。
优先减少冲突、重复输入和无必要任务；不靠隐藏坏响应、自动填字段或修改原标签获得成功。
若协议设计本身妨碍任务，允许重做，但先证明新合同能表达正常/错误/恢复路径且符合整体资源边界。
不得只优化单次调用而忘记真实生成、工具、修订、终评共享预算和 Worker 生命周期。

| 证据层 | 可以说明 | 不能冒充 |
|---|---|---|
| 静态/离线回放 | 确切合同冲突、算术、身份和状态转换；脚本路径是否可达 | 模型会理解或稳定执行 |
| 聚焦软件回归 | 原软件故障消失、相关正常与边界行为保留 | 模型质量、数据库事务或审美全部过关 |
| 真实模型开发验证 | 该版本在已核对案例上的判断、实际改文与错误行为 | 未跑的案例、跨版本资格、独立 holdout |
| 同版本业务回归/独立评估 | 采用标准下的代表性质量和剩余风险，按既有退出条件评估 | 绝对零错误保证或未执行的生产部署 |
| 真实集成/用户界面 | 同一任务/来源/结果在 Worker、DB、API、界面的实际行为 | 只因能展示就认定建议正确，或无溢出就认定审美合格 |

与改动相称地复现原问题、检查应通过的正例和应拒绝的负例、检查邻近回归，再验证相关整链。
统计修复成功要看实际改文和来源，不只看 verdict/score。假阳性、假阴性、协议失败、超时和未知结果分开记。
开发例可以反复用于定位；重复调过的材料不是独立测试。标签留在评测端，模型不接收预期答案。
准入所需完整覆盖沿用既有标准；不在过程中加专门词义定义或未经批准的额外业务条件。

必要测试通过且没有新疑点就继续，不新增复述实现的测试，不因文档改动重跑模型或全库。
提交/CI 绑定遵守已有合同；不擅自放宽，也不在其外新增“一条命令一次提交/CI”的流程。

## 6. 失败后的继续、停止和改变方案

| 观察 | 应采取的动作 |
|---|---|
| 明确的本地实现错误 | 当场修复，跑受影响回归，继续工作包，不等用户催促 |
| 无效请求/矛盾合同 | 先修已定位的构造或合同；没有合法路径时不花钱要求模型碰巧配合 |
| 完整返回但业务错误 | 保留语义失败，检查来源/任务/评判自身；针对竞争解释诊断，不拿结构通过抵消 |
| 传输/额度/超时失败 | 分开请求与整任务预算、Provider 与本地生命周期；此结果不回答语义问题 |
| 同类失败再次出现且没有新信息 | 停止该方法的付费重试，检查工作包方案；保留有效部分，废弃无效变体或改做能区分解释的诊断 |
| 证据支持修法且相关检查通过 | 更新状态，直接推进真实消费或下一依赖，不再反复证明相同事情 |
| 涉及改变用户采用标准、范围或未授权成本 | 先完成可独立工作的具体方案和证据，再按已有边界请求必要决定 |

“停止失败批”不等于停止整个项目。继续可独立的诊断、修复或产品工作，但不能拿外围产物掩盖主阻断。
不预设任意重试次数来冒充科学方法；遵守现有每批/每报告硬上限，并在每次新开实验前检查信息收益。
不保证每个假设一次成功；要求每次失败缩小未知或否定方案，否则改变方法，而非靠换候选号重置失败历史。

## 7. 防止说得正确、做回旧路

在开始工作包、出现反证/同类失败、准备声称完成这三个自然节点检查，不对每个命令加审批。
开始时写工作卡；结束时把实际改动/证据与目标逐项比对，偏离之处说明纠偏动作。
进展只认业务缺口减少、机制被证实/排除、产品可用路径增长；文档、提交和测试数量仅作支撑。

| 既往老毛病 | 后续可观察的制约 |
|---|---|
| 阶段目标被评审器实验替代 | 工作卡必须指向 Agent 任务和下游消费者；当前状态列出尚缺的产品证据 |
| 抓住最新小错连续修补 | 定位首次偏离并复核整链；外围缺口列依赖，不抢主阻断优先级 |
| 加规则引出更多字段/预算错误 | 新合同先检表达能力/合法恢复/整任务负荷，说明移除或替换的旧复杂性 |
| 标准漂移、正确话被判错 | 引用已采用完整上下文标准；正反例都验证，措辞建议不升级为事实门 |
| 模拟成功冒充真实，单次成功冒充稳定 | 每项结论写证据层和适用版本；缺哪层就明确未完成 |
| 猜根因、忽略相反实验 | 假设保留反证栏；撤回错误结论并同步当前状态，不能只在聊天道歉 |
| 反复复盘/请求授权拖延 | 一个活动工作卡，复用既有证据和授权，明确下一动作；普通问题直接处理 |
| 省额度/Luna改变产品策略 | 开发协作与 Flash/high 分开；产品模型和预算从合同读，不从协作偏好推断 |
| 因一个关卡丢掉前端与训练 | 维护下游依赖表，用户新需求记原追踪入口；解除依赖后推进，不只口头“没忘” |
| 每次重启又恢复旧方案 | 短 canonical/活动计划只放当前行动，历史单独归档；校验机器与人读的下一步一致 |

本轮按上述十类历史失败做文档反例审查，识别并纠正本方法第一版的优先级、单例诊断及旧指针问题。
这是执行约束审查，不是新的模型测试，也不是独立 Agent 审查。后续应以实际动作是否遵守、
有效诊断耗时/费用、问题是否复发和业务交付是否增长检查成效，不给自己凭文字打“已改好”的分数。

## 8. 持久化、沟通和全局规划

AGENTS 只保留方法入口及关键执行边界；canonical 记录实际状态；task_plan 记录活动工作卡/依赖；
