# 自然互补职责：语义反例与同版本资格门槛

2026-10-15。零付费、离线设计，不改变 `1.6.0` 候选合同、默认入口或发布门。

## 已确认的结构反例

逐字补丁可以通过来源引用合法性、锚点、重叠和报告组装检查，却仍然没有语义通过证据。当前离线见证覆盖：

- 数字错误、范围扩大和无依据因果；
- `source_ids=[]`，仅靠结构校验无法确认解释和修法的来源支持；
- 补丁落在与 issue 无关的合法报告段落；
- 在逐字补丁中删除全部 `[K#]` 引用后仍形成结构合法的新稿；
- 两个职责给出不一致意见时，调用方传入 `conflict_status='clear'`。该字段不是认证过的冲突判断。

空来源并非一律非法：任务缺项可依据实际用户要求说明，不一定引用比赛统计。
无知识引用也要按适用性判断，不能把不适用的知识强加给任务。跨段修改可修直接影响的摘要；
本次错目标反例则只修改无关第6段，已知第4段错误仍保留。因此不为这些字段增加一刀切语义门。

直接补丁预览保存原样意见与改文；自然应用集成还核验六次共享调用、实际应用后的同稿双fresh、
Trace/receipt和Harness拒发布。替身即使把上述反例全部判为pass，最终仍是
`candidate_repaired_pass_unqualified`，`report_available=false`、Host语义未核验。
这证明未认证结果不流入发布，并不证明程序识别了这些错误。

## 六项开发Host工作如何对应产品路径

| 开发审查义务 | 当前候选中的实际承担者 | 尚缺证据 |
|---|---|---|
| facts完整意见及全部修法正确 | facts初审策略要求自己意见正确；程序保存意见/补丁 | 模型实际解释、来源和修法的质量 |
| completion完整意见不补造任务 | completion初审完整读取用户要求；自己的说明仍须事实正确 | 实际漏项、误报和越权修法的质量 |
| 两意见兼容 | 程序只拒重叠；自然候选没有caller clear门或独立兼容服务 | 不重叠的语义冲突不会被锚点证明为无冲突 |
| 实际新稿四项ReportAssessment | 唯一原样应用保留未替换字节；双fresh读取实际完整新稿 | 修改片段的事实、正确内容保留、身份和修复是否充分 |
| facts-fresh | 现有完整事实职责请求 | 双fresh可能共同漏判或误报 |
| completion-fresh | 现有完整任务职责请求 | 不能凭模型pass推定知识消费与实际任务已满足 |

因此暂不增加第7次模型或把开发Host作为免费运行时步骤；也不通过关键词、非空来源、
数值正则或caller flag伪造通用语义检测。当前组合可做研究候选；产品自动语义门仍待选择和验证。
旧有公开回执与本次替身反例只支持这个限制，不能证明某个新自动策略已经有效。

## 同版本资格的必要门槛

完整15的既有要求保留。当前1.6.0请求清单只绑定这份研究候选；若之后改变策略、合同或发布门，
必须重新绑定最终组合，不能把研究清单或旧成功迁移为新身份的资格。未来同版本验证应具备：

1. 保留15个原输入、原标签和所有历史分歧。标签仅在评估端使用，不注入模型请求；不得拼旧意见、旧封存成功或缺认证项。
2. 同一份完整输入、来源、原稿和用户请求进行双初审。正确稿双pass时直接结束，不要求编辑或fresh，也不记编辑消费证据。
3. 需修订时，核完整意见、全部补丁、来源支持、语义兼容和实际新稿四项质量；唯一应用后，对同一实际新稿完成两个fresh。非重叠和issue_ids齐全不替代语义评估。
4. 独立开发评估核完整来源与实际意见/新稿；这是评测证据，不能冒充产品运行时服务。拒绝或分歧不能认证；身份、协议、预算、来源、观测、回执或传输故障应按具体执行方案停止，不重试或补签。
5. 未发请求保留实际原因。双初审通过后按设计跳过编辑/fresh合法，故障后的未发不补齐成已完成。unknown、receiptless和发送未知分别记录，不能填0。
6. 同一自然任务仍共享6次/401920tokens/900秒、实际单请求300秒；工具轮次、生成和全部审查均占账本。固定报告测试不证明自然生成、900秒完成或产品消费质量。

## 可重建清单与决策

`python -m scripts.audit_natural_duty_qualification` 只读原coverage、dataset、完整来源和候选资产，

结果 `data/evaluation/results/natural_duty_qualification_inventory_20261015.json` 含15个input/report/
dataset摘要、5正确/10错误原标签和两个职责的请求摘要/输入上界；没有报告正文、模型回执或Host结果。
原始JSON字节中的历史标签与评估记录不改。

若15例恰按预期路径完成，固定报告部分为50次审查（5×2＋10×4）；这只是覆盖计数，
不构成新批、费用提案、授权或自然生成证据。fresh的SHA留空，必须在实际新稿产生后计算。
清单显式为 `qualified=false`、`execution_ready=false`、`execution_authorized=false`。

当前决定是保留不可发布研究候选，结束“补字段就能证明语义”的路线。下面的离线信息探针只
选择保留义务的下一项研究机制，不构成全部语义缺口的解决方案；不直接重买完整15。
产品资格、自然消费、四块联动/journal、前端头像审美、Memory、身份运维、两树整合、独立评估
与学习依赖保留；可独立的零付费工程不由这份设计冻结。automation继续PAUSED。

## 原稿保留义务的信息缺口与离线原型

当前 `NaturalDutyWorkflow` 的两个fresh只从实际新稿构造请求，完整来源/任务仍在，但没有原稿。
因此两份不同原稿经过修改得到同一新稿时，两个fresh收到的内容各自完全相同。来源可以帮助判断
新稿本身是否有错，却不能恢复这次修改具体删除了什么。这是相对原稿的保留义务缺少输入，
不是旧语义失败的已证根因，也不表示两个历史不同的新稿一定应有不同终审判定。

`scripts/probe_natural_duty_preservation.py` 形成了可复现见证：从已有全文删除一个现存段落，
与原稿本来就没有该段的路径比较。终稿和来源相同，现有两职责的fresh请求逐字相同；加入原稿后
两条路径的输入不同。探针没有给这两条路径编造语义标签，也没有认定被删内容必须保留。

| 选择 | 对这个缺口的作用 | 决定 |
|---|---|---|
| 增加字段、强制来源非空或禁止删段 | 没有补回原稿；还会拒合法纠错、无知识适用任务或必要跨段修改 | 不采用 |
| 再调用一个相同的终稿审查 | 仍然缺少原稿，也超出现有普通修订六次路径 | 不采用 |
| 把初审结论和修法交给fresh复核 | 可看修改意图，但引入先前判断锚定；削弱当前独立新审查 | 本探针不采用 |
| 同一来源下完整原稿加实际完整新稿 | 增加比较保留/变化所需的信息，保留两职责和不看旧意见；仍有原稿错误的锚定风险 | 仅选为离线研究原型 |

原型保留现有fresh的全部来源、用户任务、新稿和输出工具；只补充未信任的完整原稿及摘要，
不筛选“重要句”、不注入意见/分数/旧标签，也不加入新的ReportAssessment通过布尔值。
facts核事实与范围的修改影响，completion核任务/身份/适用知识和有用建议的保留；均须先完整
独立审新稿，再在本职责内比较。正确等义改写、合理去重和删除原稿错误可接受；不能规定原稿
文字一律保留。删除问题定位新稿对应章节现存段落，不沿用可能已经变化的原段号。

原型严格校验两稿除报告及索引外的输入一致。它只接受调用者提供的两稿；尚未与真实application
回执绑定，不能称为实际消费。请求使用独立offline元数据，现有1.6.0 Provider明确拒收；没有
Runtime/Worker/API注册、sender、付费入口或新的候选合同。现有1.6.0初审、fresh与发布门不变。

机器结果 `natural_duty_preservation_probe_20261015.json` 保留摘要而不保存正文/意见。
原15的30个“原稿等于新稿”输入形状探针最大上界55916，原fresh最大49258，单请求增加
4904—6720上界tokens；这些不是30次执行，也不是实际改稿fresh证据。两个各自合法的长报告
仍可令组合超64000，测试确认直接拒绝；后续实际两稿必须重算，不裁剪来源或扩大输入预算。
若以后接线，新增输入仍须计入共享401920tokens/900秒，六次不增加且不保证能完成。

新增8项与既有清单4项合计12项socket阻断检查通过：完整原稿/实际逐字预览稿/来源保留、
不同原稿可区分、来源与索引篡改拒绝、旧Provider身份拒收、超限拒绝及结果可重建。
这些只证明数据可见性和工程边界，未证明任何模型的漏检率、误报率或改文质量。

## 下一项区分性验证

先构造完整来源的成对开发材料，再决定是否值得形成新身份和最小付费提案：同一来源/终稿下
比较“正确且有用内容被删”与“原稿没有该内容”；同时纳入删除原稿错误、合理等义保留和真实
错误仍留在新稿的控制。基线与比较原型使用相同终稿，评估端按完整上下文给依据，不能只根据
字面差异造标签。旧15标签与历史Host裁决不更改，熟悉材料不充当holdout。

若比较输入仍不能表达合法删除/保留，先否定原型；若实测只增加误报或未改善，停止该机制，
不靠追加字段或整批15重买续命。若有支持，也只支持保留义务方向，后续仍要同版本核初审意见、
修法、非重叠语义冲突、真实新稿及独立评估。修改效果的fresh检测不等于应用前兼容已经认证；
本原型没有把任何原要求删掉，也没有将六项开发Host工作声称为已自动实现。
