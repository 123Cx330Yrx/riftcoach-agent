# Portal 动效视频路线全程复盘

日期：2026-08-28  
范围：从第一次把视频生成作为 Portal 全局 loop 方案，到 Kling B2 结果  
当前裁决：`method-review-hold / no-new-paid-call / production_media=0`

## 先给结论

这条路线没有“只差最后一个模型”的证据。已有结果反复指向同一个结构性问题：我们把一张扁平母图交给
不同的首帧、首尾帧、图片参考或视频+图片模式，要求模型同时完成结构保真、五层空间关系、左中右均衡
运动、局部 burst 和无缝循环。模型可以完成其中一两项，却会把运动坍缩到最显眼的 Rift/水晶，或用
镜头漂移、亮度脉冲、硬光柱、圆环和稀疏星点制造“看起来有变化”。

因此当前不是继续堆 prompt 或换品牌，而是暂停付费整景生成，先建立可见、可控、可移除的分层材质载体。
视频模型能力上限仍保持 unknown；当前整景输入/控制形态已经足够证明不适合继续盲抽。

## 三条路线分别被证明了什么

### A：整景生成式 I2V / 首尾帧

首尾同图有利于首尾外观回收，却会把模型推向“插值或局部呼吸”，不提供区域遮罩、遮挡关系和材质载体。
Seedance v3/v4、Wan、Veo 的共同模式是：source/构图有时保住，运动分配不对；要么中央独演，要么用镜头
漂移换取明显变化。A 线暂时暂停，不是永久否定某个模型。

### B：真实视频编辑 / 时间与区域控制

即梦 Smart Edit 证明真实视频编辑比静态首帧更接近需求：三大区能被标注、全幕 coverage 更好。但它仍会
发生 source drift、非固定编码和 seam fail；Kling B2 证明“视频+图片参考”如果没有可验证 mask/时间语义，
仍会回到显著主体优先。B 线只有在供应商明确暴露可复核的区域/时间控制时才值得下一次调用。

### C：分层材质 + 确定性合成

C′ 证明镜头、结构、时钟和 seam 这部分是可控的；旧 C-line 线条/HUD proof 和 C′ 轻微位移 proof 说明当前
素材层还不够真实、运动幅度和遮挡也不够。C 线不是继续加透明度，而是先补齐可见的材质/遮挡层，再让
确定性 renderer 负责循环；模型只负责有机 plates 或局部纹理，不负责重画整座建筑和地图。

## 贯穿全程的根因

1. **表示方式不对**：母图是 flattened bitmap，缺少 background/midground/foreground、Rift 内外、道路/反射、
   水晶折射、右侧星图/地形和近中远空气的独立层及遮挡补全。
2. **模式能力与目标不匹配**：first-only、same first+last 和 image-only 都没有可靠区域/时间控制；video+image
   只有在服务商真正解释这些输入时才有用，不能从字段名推断能力。
3. **Prompt 负担过重且可被捷径满足**：我们多次把“保几何、全幕运动、局部 burst、首尾闭环、冷蓝材质、禁止
   HUD/漂移”塞进同一段文字。`breathing`、`fluid depth`、`vertical swell` 这类词没有指定可观察的材质载体，
   模型就用硬环、亮柱、星点或曝光变化交差。
4. **评价信号不够语义化**：MAD/SSIM 能告诉我们“像素变了”和“首尾像不像”，不能告诉我们变的是道路材质、
   真实折射还是廉价亮斑。每次必须先做人工逐区域/逐时间窗审片，数字只能做辅助门。
5. **我们自己的流程曾经漂移**：用户看到中间产物后我们多次重写 prompt、切模型和改模式；每次局部修正有理由，
   但没有足够早地把“整景生成”提升为待证伪的方法假设。B2 之后这个假设应正式降级，不再靠下一品牌证明。
6. **好的边界其实一直在工作**：失败样本都没有进入 `web/public/assets`、manifest 或 runtime；Key 没有写盘；
   失败调用大多一候选一 POST、无自动重抽。真正缺的是尽早停止同类方法，而不是再多一轮生成。

## 复盘后的新执行蓝图（现在只规划，不执行）

### Phase 0：冻结验收，不再改母图

- v2 母图 SHA `8134c0ca…1a06e` 继续是唯一结构源；不再用放大水晶、重绘母图或新概念图替代。
- 把“廉价”拆成可判定反例：硬圆环、实心光柱、孤立金星、全屏雾、镜头漂移、单区独演、静态右场、贴层边界。

### Phase 1：无成本分层资产 proof

- 建立至少 6 个可移除层：远景建筑/空气、Rift 内部、道路与地面反射、中央水晶/现有光柱、右侧星图/地形、
  前景近景粒子/金属高光；补齐必要 inpaint 背板和遮挡边界。
- Image2/Photoshop 只用于具体的 mask、背板和纹理 tile，不重画 master，不把概念图送进 runtime。
- 每层都要写清楚“运动载体”：低频流体/折射/反射/视差/空气层，而不是泛化的 glow 或 line。

### Phase 2：确定性 8s/1080p renderer proof

- 母图结构和镜头永远不 transform；每层使用不同周期/相位/低频位移，形成从首帧开始的全幕运动。
- 左/中/右、near/mid/far 每 0.5–1s 都人工审；central swell 只作用于水晶内部和现有轴线，点击转场另行处理。
- 目标不是把 MAD 做大，而是画面看起来真的在呼吸，且不是贴纸。若仍显廉价，停止继续堆 shader。

### Phase 3：只有在能力被证实后才做一次模型对照

- 供应商必须明确支持：视频编辑、区域/时间输入、固定机位、无水印/可控编码和可删除的数据边界。
- 如果不能表达同一层级的控制，不再购买新生成；Kling/Veo/Seedance 的模型上限保持 unknown，但该模式不再合适。
- 通过视觉门后才进入 Portal runtime，再做 Account 母图和五英雄层；失败则保留高质量静态 poster + 语义激活，
  不把低质视频当成成品。
