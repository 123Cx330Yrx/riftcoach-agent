# ADR-0094：采用 GLM-5.3 Flash 加固领域 V3 有界修订设计

- 状态：Accepted for design
- 日期：2026-09-04
- 范围：Stage 8 / 8E / 8-Advanced / candidate-only evaluation

## 背景

RQ-230 的 V2 真实观察已经证明 Provider、Agent、`knowledge.search`、两个证据来源和注入检查
可以完成；真正的拒绝发生在独立事实核验与 85 分质量门。V2 执行器把 `max_revisions` 固定为 0，
所以首次评测为 `needs_revision` 时只能以 `revision_budget_exhausted` 拒绝。共享 Harness 的产品
默认合同本来允许最多一次修订，因此 V2 测到的是“零修订首稿”，不是完整产品评测闭环。

回执按 body-free 规则没有保存报告正文或评测问题详情。这保护了数据边界，却也使失败只能归因到
`fact_check_failed` 和 `80 < 85`，不能知道是哪一类问题占主导。下一版本需要同时验证真实产品已有的
一次修订机制，并提供不泄露正文的可操作诊断。

## 方案比较

1. **只增加诊断，继续零修订**：能看见问题类别，但仍不验证产品已有的修订闭环；不采用。
2. **最多一次受控修订，并增加安全诊断投影**：保持质量和安全门不变，同时验证首评、修订、复评的
   完整链路；采用。
3. **降低 85 分门槛或提高思考档后重试**：会改变验收目标，且无法回答一次修订是否有效；拒绝。

## 决策

建立 `glm53-flash-hardened-domain-observation-v3`，并遵守以下合同：

- 继续使用 `zhipu/glm-5.3-flash` 候选的 `low + 4096` 专属请求策略；不改变 85 分发布门、事实、
  引用、注入和最低来源数要求。
- `max_revisions=1`，且只有首评结论为 `needs_revision`、不存在阻断性安全问题时才能进入修订；
  修订后必须再次经过同一严格评测合同，不能绕过 Harness 直接发布。
- 新公开诊断按评测轮次只保留 `attempt_id`、分数、结论、通过项数量，以及问题类别/严重度的枚举计数；
  不保存 quote、evidence、explanation、suggested correction、summary、报告正文、Prompt、reasoning、
  工具参数或请求 ID。当前评测合同没有固定章节字段，因此 V3 不猜测章节；未来只有在评测 Schema
  引入白名单章节枚举后才可增加。
- 调用墙按现有控制流的可达上界冻结：AgentLoop 最多 4 次、首次评测及一次格式修复最多 2 次、
  修订 1 次、复评及一次格式修复最多 2 次，因此每案最多 9 次、三案最多 27 次。SDK retry 仍为 0；
  调用失败不会获得额外名额。
- Token 墙不得沿用 V2 的 24,000/72,000，也不得直接按经验拍值。离线实现必须先枚举 V3 允许的请求
  包络，按冻结输入估算与每次最多 4096 输出预留形成可达性报告，再把有限数值写入版本化协议；
  预算证明不成立时不得创建 Provider。
- RQ-227 与 RQ-230 的题目和回执已经被消费，均不可重跑或覆盖。V3 必须使用全新的问题、匿名合成
  数据、case/run ID、marker、Prompt/Context Snapshot、协议和回执身份。
- 任何真实领域观察之前，先完成 no-I/O 实现与资产准入、同一实现 SHA 的公共 CI，并取得绑定新实现
  身份的新鲜 G53-3-L 协议证据；真实协议与 V3 领域调用分别需要明确授权。

## 控制流

```text
全新 V3 资产 + 一次修订合同 + 版本化资源墙
                         ↓
               no-I/O 身份与预算准入
                         ↓
          exact-SHA 公共 CI + 新鲜 G53-3-L
                         ↓
      初稿 → 严格评测 → 最多一次修订 → 同合同复评
                         ↓
        85 分/事实/引用/注入/来源硬门共同裁决
                         ↓
        body-free 结果 + 枚举计数诊断（不含正文）
```

## 边界

本决策只完成设计，不修改产品代码、不创建 V3 考卷、不读取 Key、不构造 Provider，也不发送真实请求。
它不注册 GLM-5.3 Flash、不切换默认 Runtime、不删除 GLM-5.2 手动兼容/应急路径，不改 Portal、
Account、Workbench、Auth、路由或 `production_media=0`。黄金切片、安全/部署/合规、公开发布和
8F 仍未完成。
