# ADR0115：当前来源合同下的必要编辑适配器

状态：仅实施诊断适配器，未采用为产品候选；不授权付费、不重开旧批。

## 依据与选择

2026-10-01真实claim-scope:4初评正确检错，Flash整稿修订纠正数值却把system前420字符
写进导语。详见docs/plans/2026-10-01-editor-policy-echo.md；完整原15仍未完成。
旧显式替换原型可保留未修改字节，但来源目录和终评不是当前版本，after也可能写错。
隔离实验已证明当前31/32来源与当前终评可兼容；这不证明模型生成可靠性。

本次选择把“整篇重新输出”改为“原文锚点＋必要替换”的最小诊断适配器：完全保留当前
accepted_review与来源消息、模型/high和业务标准，仅改变编辑输出表示。在已有一次revise
槽位中使用，不新增步骤或pass后编辑。初评pass/fail、fresh全文重评和发布规则仍沿原流程。
不采用仅追加提示后重开15例，也不把旧ADR0110自主来源核验的失败翻案；当前任务有真实初评意见。

## 数据与控制

`coarse_revision_editor.edit_request`从当前编辑请求构造工具提交；允许引用当前完整来源根。
`inspect_edit_exchange`绑定实际请求、Flash响应身份及工具回包，先保存实际回执再检查；
复用source_patch_editor原子组装，显式指定coarse解析器与当前完整终评构造，不动态替换模块。
长段指令复制被拒绝，不清洗、不补写。`CoarseRevisionWorkflow`只覆盖编辑请求/响应处理，
继承已接受评估绑定、一次编辑、期望终评输入和失败停止。SharedBudgetReviewSender仍是预算入口。

旧source_patch_editor默认行为保持，新的来源与终评依赖仅由显式参数选择。默认产品、manifest、
Worker及资格代码不注册此适配器。完整稿语义和引用是否正确仍由实际模型与独立全文审查验证。

## 验证与去留

离线先验真实原问题、正确稿保留、来源/回执篡改、错误工具/模型、指令污染、未知知识引用、
原子性、fresh全文绑定、单次修订和共享预算不足停止；保留旧原型回归及关闭批请求字节。
随后才冻结最小实际编辑＋条件性当前GLM终评＋正确保持控制；旧初评仅作固定诊断输入，
不能计为新原15连续资格。完整工具响应、来源、全文和保留内容都须审查，不只看通过分数。

如果模型依然改坏/漏改、工具无效或耗尽预算，保留失败，不追加变体碰运气；根据首次偏离
决定撤回此机制或诊断任务本身。能力通过也只解锁同身份回归和产品接线准备，不完成8E。
五调用、401920tokens、900秒共享上限不变；样例225160下游预留不代表所有任务都能容纳。

摘要。顺序是Flash必要编辑→双审接受全文→当前GLM fresh→双审接受→Flash正确保持对照。
最多3调用、290304tokens、900活动秒、86400独立宿主等待秒；未缓存保守预留1.7154048元，
不是账单硬上限。首实质、协议、来源、身份、传输、预算或人审拒绝即停，不重试/重开目录。
正确稿对照不引入产品pass后编辑；两条历史初评不计作新调用或同版本资格。

入口复用真实原生独立事件/主审attestation、StageAssessment/ReportAssessment、现有角色路由、
