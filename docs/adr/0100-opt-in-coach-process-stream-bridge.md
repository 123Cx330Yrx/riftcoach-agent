# ADR-0100: 显式候选 Coach 的进程隔离流式桥

2026-09-10计时补强：bridge进度独立schema1.1增加末次事件/正文/reasoning、最长事件间隔、open/advance/processing/close累计耗时、写入开销；调用前预约增加仅数值的角色消息规模及保守输入上界。旧standalone诊断1.0和transport内容语义不改。advance包含SDK等待/解析/归一化及trace hook，不可解释为纯网络/供应商推理；写入耗时与执行阶段重叠，当前快照不包含自身写入开销。快照是已落盘前缀，父kill可丢失末批；新observed_elapsed不截顶，旧时间字段保持兼容。下一次真实运行仍须同SHA公共证据和新鲜协议。具体方法与基准见黄金切片计划的安全分段计时节。

日期：2026-09-10。状态：接受离线实现；真实产品采用未通过。

问题：c4a169b第二请求等待响应头90秒失败；869e4b3的新报告形状请求首次完整流式观察为首事件5.453秒、首正文20.093秒、完整收尾43.328秒。不同请求不能作因果性能对照，但足以验证候选流式接线。普通线程不能保证中断阻塞SDK，增加读取超时也不限制持续零碎输出的总时长。

决定：新增独立transport `golden-process-stream-v1`，保留Coach1.3.5内容合同、high/8192、64000输入上界、9调用/8工具及质量门。仅黄金切片显式选择它；默认同步与旧回执保持兼容。每次chat创建子进程，父进程从启动前起限时不超过request.timeout_s与90秒；通过内存管道传入中立请求，子内复用ZhipuStreamAdapter/ProviderStreamAssembler组装、检查EOF/Usage/工具JSON和关闭，然后一次返回完整ChatResponse。正文、reasoning、工具参数不落临时文件或日志；reasoning仅通过内部response用于既有工具回放。子输出有序列化上界，父仅接收可信子程序的JSON而非反序列化pickle。

不采用旧candidate transport，因为它固定历史recovery身份；不引入新的依赖，不启生产streaming界面。父到期杀子并回收，任何失败后不重试且该bridge不可继续发请求；无法回收必须保留安全失败状态，不能声称上游停止计费。每调用安全进度与最终回执保留，部分输出永不交付；返回前关闭失败也拒绝。

时限精确定义：不超过90秒的是子进程模型工作截止，涵盖启动、请求、读取、正常关闭与IPC交付。到期先终止子进程，之后最多5秒仅用于回收；回执写入另计父调用实际墙钟，因此不承诺父API在90.000秒前返回。回收失败明确unreaped并禁止后续调用，不能吞掉故障后交付响应。该口径延续独立诊断的终止后回收约束，不增加Provider工作时间；上层既有Agent/整体时间预算仍独立检查。

流程：已验签输入/公共证据→现有Coach请求与调用预约→独立子进程→SDK流事件→中立组装器→EOF与关闭→完整响应→既有工具/评分/最多一次修订→质量门。工具仍由原Runtime执行，子进程只组装工具参数。结构化输出请求和工具结果回合保持原模型编码。

验证：纯组装验证工具片段、reasoning回放、结构化JSON、缺Usage/截断/关闭失败；真实本地子进程验证卡住、超时、崩溃、私有输入输出管道、没有partial交付；黄金入口默认与显式身份/预算测试及相关回归。离线通过和公共同SHA验证后才有界真实观察，不能用假SDK结果认定报告质量或生产准入。

代价与边界：每请求进程/SDK新建增加开销与连接建立；90秒包含启动、发送、读取和关闭，可能比原每阶段SDK超时更严格。SDK EOF不等于独立HTTP网络EOF；HTTP body.failed末事件可在正常SSE清理时出现，不能单字段判失败。JSON序列化只用于同一程序的本地私有管道，不作为公共接口。前端、生产Worker、默认模型不变。

## V2兼容修正（2026-09-10）

8aff7be的V1真实第一请求在15.094秒内得到tool_calls终态、Usage、EOF及成功关闭，另有38字符正文；本地组装失败，无工具执行或报告。该形状与旧assembler的content/tool_calls互斥要求冲突，而同步Zhipu.chat与AgentLoop允许带正文的工具回合。离线合成相同形状可复现tool_calls_with_content；原回执没有工具参数或具体异常码，故不能断言它是原调用唯一失败原因。

新增独立golden-process-stream-v2，保留V1可选身份及其严格行为。通用assembler新增默认false的allow_tool_calls_with_content，仅V2内部固定开启，不接受request metadata控制。只允许完整tool_calls终态同时有正文；工具JSON、唯一ID、Usage、EOF、模型身份、关闭及调用/质量预算不变。AgentLoop将其作为工具回合保存内存并执行工具后继续；它不能成为最终报告。同期子失败工件只记录受校验的StreamAdapterError内部码，其他异常一律固定worker_failed，不存SDK原文。真实V1旧回执不改写或重复执行。
