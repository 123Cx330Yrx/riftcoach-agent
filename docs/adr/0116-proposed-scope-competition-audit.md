# ADR0116: Competing-scope evidence inside one complete review

2026-10-08. Proposed; offline prototype only. No production selection, live
permission, original15 qualification, or accepted-standard change.

## Problem and rejected alternatives

The current full initial review and the subsequent complete reassessment both
reported a false issue on the omitted early-death scope in claim-scope:3. The
same response correctly found the independent pooled-CS error. The complete
source and later explicit selected-sample scope reached the model; public
explanations acknowledge them. This is a semantic failure, not lost context,
stream interruption or output exhaustion. The latest closed original15 stays
2/15. See `../plans/2026-10-08-scope-resolution-result.md`.

| Alternative | Decision and evidence |
|---|---|
| Repeat full reassessment / increase output allowance | Rejected as a sufficient fix by the latest complete response; a legal semantic error does not trigger existing structural recovery. Natural generation + initial + reassessment + edit + fresh would take six calls. |
| Narrow scope review before/after a full review | Not selected. The same four-cell design was proposed in the 9/28 strategy audit and rejected in the failure audit: no complete five-call integration, and old full fresh can reproduce the problem. Do not refreeze this as a new experiment. |
| Typed single-cohort checks | Existing ADR0102 implementation checks values and addresses but can legally select the wrong cohort. Do not revive it or claim arithmetic solves entailment. |
| Ignore false initial issues or change the source report | Rejected under ADR0111 and the existing qualification standard. No qualification migration or host rewrite. |
| Competing-scope evidence in the same full initial/fresh call | Selected for an offline feasibility prototype only. Unlike the old single-cohort witness, records explicitly expose supporting and opposing whole-document anchors for competing interpretations. Same-call generation still permits post-hoc rationalization. |

Historical controls have produced both passes and failures. None establishes a
general fix, attention/load causality, sampling reliability, or provider limits.

## Prototype responsibility and data flow

`scripts/scope_competition_prototype.py` is injectable offline code with no
Provider construction, CLI execution, candidate registration or publication.

Complete report + unchanged sources -> one complete initial review with short
`scope_checks` -> existing necessary editor -> exact assembled report -> one
complete fresh review using the same new contract and no prior opinion.

Each audit contains an exact claim, candidate cohort IDs, original block anchors,
short public evidence relations, and a resolved/unresolved selection. It requests
evidence justifications, not private reasoning or a copy of the source data.
Existing issues, corrections, citations, score, markers and all business
obligations remain. The new audit does not determine report acceptance.

The host validates exact text, addresses, candidate membership, uniqueness and
declared resolution consistency. It does **not** decide which text establishes a
scope, whether all competitors were found, or whether a number supports an
inference. `scope_audit_coverage_verified` and `semantic_approval` stay false.
Correct scope cannot excuse an incorrect mean, universal claim or causal claim.

Audit records stay in the complete raw/journal. The editor receives the existing
complete actionable issues, source context and original report; the audit is not
an additional editing instruction. This is an explicit internal projection, not
conversion of an old response into a qualified new one. Original receipts remain.
The fresh-request preview in the edit journal binds to this prototype's builder.
Malformed new reviews terminate; the prototype adds no recovery call.

## What the offline tests establish

- All 15 original full report/source inputs and existing citation restrictions
  survive request construction unchanged. Each input fits the existing envelope.
- Authored examples can represent omitted scope, explicit wrong scope, unresolved
  scope, pairwise comparison and future extrapolation without removing the
  independent pooled-CS issue. These are fixtures, not GLM successes.
- Invalid cohort, block/anchor, quote, duplicate claim, unresolved-with-selection,
  unsupported selection and source IDs reject without repair.
- **Counterevidence is retained:** empty scope audits and a plausible but wrong
  MIDDLE interpretation can be structurally legal. Human semantic inspection must
  reject a missing or wrong audit in the relevant control. No test oracle is put
  into runtime and no test says schema success is semantic success.
- The actual workflow with a scripted sender completes initial/edit/fresh in
  three calls, preserves issues, and constructs a fresh request without old audit.
  A bad protocol stops after one. This is not natural generation or live routing.
- The existing production role router deliberately rejects this unregistered
  schema. Initial attempts to test through that router exposed this boundary;
  neither its schema check nor its contract registry was weakened.

Thus two existing generation slots plus three prototype processing slots are a
**call-count design**, not a verified natural five-call implementation. Current
5/401920/900 limits and 32768/300 per-request limits remain unchanged. Real
output size, latency, task cost and full budget reachability are unproven.

## Decision gate, falsification and follow-through

Before spending on this hypothesis, review whether the extra evidence obligation
has enough value despite self-selected coverage and post-hoc explanations. Do not
build a large new source grammar, register a candidate, or freeze 15 calls merely
because the prototype is expressible. A minimal diagnostic must include correct
omitted scope and explicit wrong scope, full-report obligations, an actual
unrepaired true error, and a host audit of the scope record itself. Expected labels
stay outside requests. A missing/wrong audit or unchanged semantic error defeats
the sufficiency hypothesis; do not filter it into a pass or add synonym prompts.

Any live preparation must first resolve a separate experimental routing identity
and verify its receipt/whole-task budget without weakening current routes, then
prepare specific requests, cost limits, same-commit CI and authorization. No live
plan or new cost has been authorized by this ADR. Do not reuse the closed two-call
batch's unused call. Success would only unlock full same-identity qualification;
original15 remains 2/15 in its old identity.

This proposal does not postpone or cancel natural Coach, Review/Training/Evidence
linkage, user training goals, frontend redesign/aesthetics/hero portraits, Memory,
Worker/DB/API/Workbench, identity operations, two-tree integration or learning.
Their dependencies remain in the active plan and the 9/16 restart plan.

## 2026-10-08 adoption decision before machine transfer

Do not adopt self-selected mandatory scope records as the general fix or add their
completeness as a product acceptance gate. The one observed correct issue list is
useful business evidence, but neither causal attribution to this mechanism nor
complete coverage is established. Keep the original diagnostic rejection and all
original15 admission flags unchanged; do not drop the failed requirement to turn
that frozen batch into a pass. No field-completion retry or new paid plan follows.

Targeted evaluation can enumerate a known disputed claim before execution and
check its audit coverage. General runtime cannot use that test oracle: automatic
selection of every disputed claim is another unproven semantic task. Requiring
an additional explanation for every correct paragraph would expand work without
solving that selection problem. Independent source review confirmed this boundary.

The composed prompt also retains the base instruction not to require additional
explanations for correct paragraphs while adding records for competing scopes.
These have potential scope tension, but are not a demonstrated internal cause:
explicit evidence records and redundant prose are different obligations, and the
model's observable output cannot establish why it omitted the target. Do not
announce a prompt-conflict fix or rewrite the policy on this evidence alone.

The next technical question is how the existing full review / necessary-edit /
fresh-review task can produce a correct final artifact without relying on complete
model-authored audit coverage, under the unchanged five-call budget and original
business standard. ADR0110/0111 constraints remain: no sixth call, host answer
injection, mixed-error exception, skipped fresh review or borrowed qualification.
Work from a complete executable task contract and negative controls before another
paid plan; do not default to another schema-field or wording variant.
