# ADR0110: 来源职责与独立编辑的可行性核查

2026-09-23。状态：**离线原型已实现；独立编辑首例超时并关闭；产品架构未采用。**
本记录不修改 ADR0109 模型分工、用户完整上下文标准、原15资格或默认产品。

## 问题与目标

真实 Agent 观摩任务的 Flash 原稿把外部快照日期写成知识检索日期；GLM 初评漏检。
补齐知识时间及单条引用的来源信息后，6c3a3db 仍完整返回95/pass，并给一条正确建议
选择了不相干的指标来源。输入、报告、编号、传输及预算已核对，模型内部原因仍未知。
目标是降低这类错误进入用户报告的机会，同时保留 Agent 分析、工具、训练行动和完整质量门。

## 实际职责与控制流

当前 `ReviewHarness` 初评通过即发布。实际生成两次、初评一次后，五调用上限中仍有两次
未使用；但首评出现恢复或生成多轮时余量会减少。现有 `revise` 仅接收真实 needs_revision，
第二次 evaluate 要求已经修订一次。不能伪造 issue 或改写原 pass 借道进入这两个步骤。

生成器当前直接写完整七节 Markdown，包括来源目录。KnowledgeEvidence 已持有来源、
版本、文档更新和逐次检索时间，不必让模型自由重写固定目录。正文对来源的实际使用、
日期归属、身份/位置、复合指标、归因及训练建议仍是语义任务。

## 离线实现和决定

`app/evaluation/source_bound_report.py` 实现了一个未注册的组装原型：

1. 模型在第7节末留一个明确 slot；程序只替换该 slot，不定位并删除任何“像来源段”的正文。
2. 目录逐条从 KnowledgeEvidence 导出，重复检索、未知时间保持原义；不借外部日期补齐。
3. 原稿和成稿分别记录文本、摘要、操作及错误。失败也留原稿，不把主机呈现叫作模型改稿。
4. 修订必须保留已呈现来源块；改写则拒绝，程序不覆盖纠正。验证发生在既有终评绑定之前，
   接受的改稿字节原样进入终评、Harness 最终报告，未修改 `_expected_recheck` 私有状态。
5. 目录编号不使用 `[K1]`，所有来源值转义；来源名自己含方括号/换行也不能伪装正文引用。
   原有70%长度门只针对正文另行检查，固定来源栏不能掩盖正文大幅删减。

结构验证曾过于严格地拒绝原15中合法的描述性标题和附加小标题，已调整为识别真实标题行、
七节顺序和唯一性，同时保留这些合法内容及标题断言；未重写冻结报告或降低其语义要求。
最初直接把单参数 Harness preparer 包到双参数 SkillAgent preparer 上造成离线失败；已分别
识别现有两种结果合同，并保留原 AgentRun，实际 Runtime 五调用测试通过。

该原型已在现有 Harness 和**测试注入的实际角色 Runtime**走过两次生成/工具、
needs_revision、一次改稿、终评与文件读回；全部模型返回为脚本替身。不是新的 pass 后核验流程，
也不是产品候选接线或真实模型证据。原15只验证全文保留、来源与请求容量，未增加一次资格通过。

**不采用它作为核心漏检的充分修复。** 完整错误稿后加正确目录，保留原日期真错并重放
真实95/pass响应，现有校验仍接受。该负对照已保存，不能靠模板语法拒绝把旧例重标成“检出”。
目录方案仅保留为可复用的离线边界，本次新能力检查不同时启用，避免混杂干预。

## 下一项能力假设及历史区别

考虑在首评 pass 后仍使用预留的一次 Flash 独立核验/必要编辑，再交普通 GLM 终评。
正确稿可以保持原样；不要求捏造问题，也不把建议当阻断。正常路径仍为2+1+1+1=5，
但这只是资源与状态方案，尚未修改产品状态机、阶段路由或宣称在模型上有效。

483f91d 的定位编辑正确、完整旧意见编辑错误；6c22e93 的无旧意见 Flash 编辑修好一例，
失败的是同为 Flash 且包含原稿、新稿、旧意见和双层 decisions 的复杂终评。普通终评未实测。
这些结果既不否定本次新假设，也不证明 Flash 能补捉当前 GLM 漏检。不能重开旧两状态实验。

在改产品状态机前，先执行最小独立能力检查，脚本为 `scripts/run_independent_edit_pair.py`：

- 第一例仍是完整日期错误原稿；第二例是仅删除无依据日期的原人工参考。
- 同一完整来源、同一业务标准、Flash/high；不送旧评分、旧意见、预期标签，也不渲染新目录。
- 原有段落索引不保留空行，不能要求模型从它逐字恢复原稿。因此编辑输入额外携带绑定的完整
  `original_report_markdown`；索引与来源不变，预检包含这部分成本，不把不可恢复的排版当作模型错误。
- 输出直接为完整 Markdown。host 核对全部实际改动、正确内容与来源；正确参考应保持原样。
- 最多2次/600秒，单次300秒/32768输出，SDK retry0；预检保留161062 tokens，
  全未缓存价估算上界0.2599216元（非厂商账单）。请求与源码摘要见准备文件。
- 任一协议、事实、引用、无必要语义修改或预算失败停止余下批；不带原批剩余次数继续。
  小范围空白差异单独记录，不当作业务事实失败，也不声称逐字 keep。
- 若失败，不在该批追加提示重试，也不实现强制编辑产品分支；若成功，仅支持进入实际编辑稿的
  普通 GLM 终评验证。仍需原15、实际整链与独立评估，不能凭两例更换默认或宣布稳定。

新诊断没有注册新的产品候选。复用已有 transport、观察/用量/中途host裁决和停止机制。
以下执行结果取代准备时的“尚未调用”状态；原冻结计划和原始失败记录不改。
执行失败除保留JSON结果外也返回非零退出码，避免调用方把正常进程退出误读成实验成功。

## 实测与方案回退

58449abb / CI35843805636三项通过后，按用户既有连续诊断修复授权及当前继续指令执行。
这不是用户新逐字批准“两次”的回复，也未借用已停止v2的剩余次数。冻结独立编辑批实际
只发1次，在300秒截止；最后事件299.968秒，12800个事件、最大间隔1秒，正文0字符、
无终态和usage。第二例未发送。真实用量/费用未知，已知累计0不能写成总费用0。
原始9份工件、执行身份、请求重建和独立核验见golden_independent_edit_result_58449abb.json。

该结果是执行未完成，无法裁决是否修对日期或保留正确全文；不证明模型语义能力不行，
也不证明网络断流或输出上限耗尽。拒绝据此接入pass后强制全稿编辑，关闭原execute入口，
不加时、不重试、不发送第二例。历史6c22e93独立编辑在同一300秒/32768上限下74.735秒完成，
但两次报告、来源、政策和表示都不同；输入从24232增至30010字符不能独立证明超时由长度导致。

方案选择中还遗漏了一个更直接的比较：当前日期稿仅做过GLM审查和Flash整稿编辑；
346213c的Flash审查针对旧归因稿，并非日期稿。因此先补同输入Flash审查对照，复用现有
needs_revision→改稿→终评的可能路径，暂不实现新的pass后状态机。

`scripts/run_flash_knowledge_time_review_pair.py`复用已关闭v2的纯离线请求构造及既有observer：
原方案两请求与v2冻结请求逐字节相同，775f7bbf / CI35846295212三项通过，但付费前的
全文标签复核发现：原“正确参考”第5节仍把2026-09-10赋给两条不可用OP.GG记录。来源31仅有
digest/reason，没有OP.GG或整个包共同的retrieved_at；来源32/33的日期各自属于补丁/Data Dragon，
不能代填。因此撤回原参考的完整正确标签及尚未执行的Flash v1计划（0请求），旧工件不改。
这是主Agent与此前独立审查共同漏掉的验收材料问题，不能归咎于模型，也不意味着旧漏检失效。

新参考以原稿为起点只删除两处无依据日期，保留全文，其摘要为d3afdb4d…37303。
独立按七节、全部数值/来源/身份/建议复核，没有发现第三个阻断。死亡窗口03:26–13:24确有
原始timeline数据；“26分钟内”、常见定位定性和相对量级措辞按全文保持非阻断，未新增词义门。
依据、两处变更及精度边界保存在golden_source_time_reference_audit_v2.json；人工参考不是模型改稿。

当前v2计划：错误稿仍与GLM真实出站字节/hash相同；新参考只改报告和派生摘要，事实、政策、
工具schema、high、32768/300秒和SDK retry0均不改。第二份GLM未实测，不能说已有同题结果。
最多2次/600秒/164158tokens，未缓存估价上界0.2623984元；现有连续授权覆盖该同目标、有界诊断，
当前仍须本提交公共CI后执行。旧错误稿需检出两处时间问题，新参考应通过；host核对实际全文，
标签不得发送给模型，不把检出真错记成误报。
每例核对全部issue/advisory和引用，任何失败立即停批，不改提示重跑。

若通过，只支持准备现有流程的真实改稿和GLM终评，不证明Flash更优、稳定或错误独立，
不直接改产品角色路由。若失败，该审查器替换同样不得采用，转入任务职责/完整流程方案选择，
不再排列日期字段、提示或模型变体。最终证据文件存在时execute在输入/凭据读取前关闭，
防止新工作树或新运行目录重开已结束批。默认产品、质量要求和原15均不变。

## 取舍和采用前要求

| 备选 | 决定与理由 |
|---|---|
| 再补字段/一句提醒重跑 | 不安排，已排除关键时间缺失，未获新的区分信息 |
| 静默删错误来源段或覆写编辑结果 | 拒绝，会隐藏模型错误并污染回执 |
| 固定来源目录 | 工程边界可用；不消除正文漏检和错引，不单独晋级 |
| 给所有任务追加第六次审查 | 不采用，超出既有调用预算且不能保证错误独立 |
| 使用预留编辑机会独立核验 | 本次300秒无正文，暂不采用、不加时重试；保留原失败 |

未来若采用 pass 后核验，必须在正式 ADR 更新中明确原状态迁移、阶段身份、真实保持/编辑结果、
预算不足时拒绝而非跳过终评，以及普通 GLM 对实际成稿的完整审查。不能将两个实验的成功拼成整链。
默认模型、原始失败、旧15输入及主工作树前端未变；Worker/DB/API/Workbench消费、四块联动/
个性化训练、前端审美/必要重做/英雄头像、Memory/RAG、身份运维、两树整合和学习仍在原路线中。
