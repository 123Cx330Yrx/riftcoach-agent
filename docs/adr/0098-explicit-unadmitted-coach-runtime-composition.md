# ADR-0098：显式未准入的 Coach 产品运行时组合

状态：Accepted for offline implementation；2026-09-06，RQ-245，8E。

背景：RQ-244 证明开发入口的固定输入预算，但普通 Runtime 还没有绑定查询、报告、来源和单次重试规则。
直接改默认会混淆候选证据与生产状态；复制一个新评测执行器又不能证明产品链路。

决定：扩展现有 RuntimeExecutionFactory / AgentRuntimeV1 的显式合同接缝，不创建第二套运行框架。
新组合 recent-form-review-flash-v2@1.0.0 使用现有候选 low/4096 请求策略，绑定独立 Skill 0.3.0 / 程序 2.0.0。
普通模型解析器、生产 Provider 注册、默认 Skill/程序目录与 GLM-5.2 不变；目标运行档案 v2@2.0.0 仍未注册。
因此 Trace 记录实际的未准入组合与请求策略，不伪造已注册的 v2 runtime_profile。这细化 RQ-244 的迁移目标，
并非取消最终产品 v2；正式注册仍在独立真实验收后。

控制流：显式组合→产品请求编译→现有 Runtime→Memory 内层可信 Context→检索→报告→评测/一次修订→证据与 Trace。
组合身份及摘要同时进入 policy/identity，旧记录不写新字段；程序指纹覆盖同一查询、报告和预算参数。
初稿来源至少 1、结构与引用验证、85 分及安全门不变，确定性回退关闭，SDK/工具均无额外重试。

资源：每请求输入估算不超过 64000（四倍 16000 Context 限额的独立包络），输出最多 4096，九调用总墙
为 9×(64000+4096)=612864；不是声称任意输入可接受。逐请求完整测量，超过单请求包络在 I/O 前拒绝。
单请求超时参数上限45秒、Agent整段90秒；执行束的模型调用计时360秒涵盖90+5×45及余量，
在调用前/后检查，但不宣称覆盖所有非模型步骤，也不能把SDK同步取消当成已验证硬实时能力。
Worker lease保持360/heartbeat60，测试所有权丢失后不能提交用户可见终态，不要求删除内部诊断产物。

替代方案：直接替换默认（拒绝，未真实准入）；复制领域执行器为 Worker（拒绝，旁路正式 Trace/产品合同）；
新增统一编排框架（拒绝，无必要）。代价是保留独立资产根与显式组合参数，收益是可验证迁移与旧路径兼容。
不新增依赖，不改前端/Auth/路由，不重跑已消费考卷。验证使用 fake Provider/SDK、本地检索、真实 Runtime 与 Worker 类。
