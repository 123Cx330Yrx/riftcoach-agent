# ADR0113 — 将修法范围责任接入既有角色运行链

2026-09-27。采用显式工程接线；完整质量与生产准入尚未取得。

## 问题与证据

1.5.3 原15在第四例识别真错后又给出错误经济归因修法，严格资格停在3/15。
保留全部来源与输出字段，仅约束修法不扩展未确认的问题，两控制真实全文双审通过；
随后Flash实际修正伤害归因，fresh GLM终评94/pass，双审接受。

16a0dce6c0b12777fa78506765a78827a2d647e07ee5857ab16e9a3c009bd12f。
该证据支持接线，不证明采样稳定性，也不能抵扣同版本原15或自然Agent资格。

## 决定

新增显式opt-in合同1.5.4、Program3.3.0、evaluation3.7.0；Skill0.6.2的业务指令未变。
产品模块保存与实测逐字一致的范围责任规则，初评、fresh终评和已有一次有界重评
由同一策略函数生产并指纹化；编辑继续接收完整意见。来源表示、输出schema、模型角色、
high档及共享5调用/401920tokens/900秒预算不变，SDK retry0，最多一次报告修订。

保留产品原有一次重评而非直接复制诊断的禁止逻辑，避免同时改变恢复行为。
原15严格执行仍禁止重评、错误解释例外和重试；恢复分支单独做工程验证，不能冒充真实证据。
复用应用builder底座、工具/RAG/Memory/发布机制、观察执行器、双审交接及封存资格审计。
默认Worker与生产开关不变，不新增模型或状态机。

1.5.3的请求策略、descriptor/snapshot及历史封存保持不变。共享代码指纹改变时刷新
当前可运行manifest，历史资格仍绑定当时冻结manifest；新规则从0/15起，不拼历史成功。

## 验证和后续

检查全部15请求的来源/schema/参数不变、与诊断策略逐字相同、编辑意见无损、
重评保留原问题且同策略、实际应用生成/工具/审查/保存、共享预算和可信Trace。
新旧合同与资格不得互相冒认；独立复核接线与相关回归后再冻结同HEAD真实原15。
