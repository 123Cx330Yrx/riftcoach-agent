# ADR-0025：真实领域门前必须先证明资源合同可达

- 状态：Accepted
- 日期：2026-08-15
- 阶段：5D-7

## 背景

DeepSeek V4 Pro V2 held-out 首例在一条真实规范化响应后累计 3440 tokens。账本为
下一请求预留 1024 output tokens 时超过单例 4000 上限，于 Provider I/O 前停止。
因此，V2 没有运行到完整报告与 Evaluation。

此前离线纵向测试使用极小固定 Usage，只验证了控制流，未验证真实请求长度与资源合同
是否相容。

## 决策

1. V2 结果维持不可变的 `admitted=false`，不修改、不删除、不重跑；
2. 不把 V2 解释成 DeepSeek 领域质量失败，模型质量结论保持 unknown；
3. 新的真实领域门在构造 Provider 或读取 Key 前，必须通过离线预算可达性门；
4. 可达性证据必须区分：
   - 真实 Provider Usage 支持的精确结论；
   - tokenizer-free 请求长度支持的校准投影；
5. 投影不能被描述为官方 Token，也不能单独决定新预算；
6. 当前允许继续做 V3 的资源合同设计与开发校准，但在新预算、新输入身份、新结果路径
   和公开 CI 全部冻结前，不授权任何 V3 Provider I/O。

## 备选方案

- 修改 V2 预算重跑：破坏 held-out 与不可变结果语义，拒绝；
- 立即关闭 DeepSeek 候选：把实验设计失败误判为模型能力失败，拒绝；
- 直接采用一次长度估算作为 V3 预算：具有虚假精确性，拒绝。

## 后果

正面后果：

- 以后不会再用不现实的 Fake Usage 宣称真实链路可达；
- 模型、Agent、Harness 与实验资源失败可以被分别归因；
- 新一轮真实调用前有明确的 Key-last 决策门。

代价：

- 在 V3 之前增加一轮开发校准；
- 当前不能给出一个看似精确的 V3 Token 上限；
- DeepSeek、Flash 与 GLM 比较继续等待相同口径的领域门。
